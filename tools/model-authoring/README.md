## 守ること

1. **パーツは画像生成AIで作る。毎回、元画像を添付する。** 元画像の画素を切り取ってパーツにしない。元画像は、生成の見本と、合っているかを測る物差しにだけ使う。
2. **合わせるのは、縦横同じ倍率と平行移動だけ**（必要なときだけ小さな回転）。縦横を別々に伸ばさない。例外（体の上下で倍率をなめらかに変える、など）は計画に記録する。
3. **生成の前に計画を書く。** `projects/<id>/modeling-plan.md` に、パーツの一覧と「決めてほしいこと」の表を書き、ユーザーの答えをもらう。
4. **ユーザーがアプリで直したあとは、組み立てスクリプトで作り直さない。** 直した所（ワープ・輪郭線・キーなど）が消える。直すときは、保存されている project.json だけを変える差し替えのスクリプトを書く（例: `projects/cardigan-bob-20261010/authoring/round_mouth.ts`）。差し替えは、ユーザーにアプリを保存して閉じてもらってから行い、前の版を `backups/` に残す。起動中のアプリと、project.json より新しい自動保存（`backups/autosave-*.json`）があるかを先に確かめる。
5. **開発サーバー・アプリの更新・e2e は、`.cache/locks/main.lock` を取ってから。** 起動しているアプリ（live2d-studio.exe）は、断りなく閉じない。

## 道具（このフォルダ）

道具はリポジトリ（このフォルダ）に、画像と設定はプロジェクトのフォルダ（`projects/<id>/`。Git の管理外）に置く。どの道具も、プロジェクトのフォルダを環境変数 `MODEL_PROJECT` で受け取る（`mauth.py`）。確かめ用の画像は `projects/<id>/checks/` に書く。

```powershell
$env:MODEL_PROJECT = 'projects/cardigan-bob-20261010'
python -I tools/model-authoring/grid_check.py lowerLidR
```

```bash
MODEL_PROJECT=projects/cardigan-bob-20261010 python -I tools/model-authoring/grid_check.py lowerLidR
```

プロジェクトのフォルダの形:

| 場所                          | 中身                                                                                  |
| ----------------------------- | ------------------------------------------------------------------------------------- |
| `reference/`                  | 元画像（`original.png`）、白抜き版（`original-ref.png`）、拡大（`zoom-*.png`）、見本  |
| `authoring/parts.json`        | パーツごとの依頼（型・拡大・プロンプト）                                              |
| `authoring/zooms.json`        | 拡大の範囲と出力の大きさ（`{"box": [x, y, w, h], "out": [W, H]}`）                    |
| `authoring/measure.json` ほか | 元画像で測った値（目の開き・輪郭の窓など）、組み立ての設定（目・口・揺れ）            |
| `authoring/composite.json`    | 描く順・切り抜き・休みの姿勢で隠すパーツ・不透明度（`composite.py`・`grid_check.py`） |
| `parts/<part>/<part>-vN.png`  | 生成した画像                                                                          |

| `project.json`・`assets/`     | 組み立てたモデル                                                                      |
| `preview/`・`validation/`     | 報告に使う画像と、測った数値（配置: `placement.json`・`landmarks.json`）              |

**モデルごとに直す所:** 描く順（`authoring/composite.json`。`composite.py` と `grid_check.py` が使う）、`raster.py` の確かめる範囲（目・口の枠）、`colormatch.py`・`landmarks.py` の色の指定、`turnref.py` の層の割り当て（`authoring/turnref.json`）、`align_round_mouth.py` の拡大の名前。組み立て（`build.ts`）と差し替え（`round_mouth.ts`）はモデルごとのスクリプトで、`projects/cardigan-bob-20261010/` にある例を写して直す。

**画像生成:** ChatGPT アプリに入っている Codex CLI を使う（`mauth.codex_exe()` が場所を探す。`CODEX_EXE` で指定もできる）。利用の上限がある（約100回で止まった例がある）。始める前に、短い依頼を1回して使えるかを確かめる。

## 流れ

| 段階            | やること                                                                    | 終わりの条件                                     |
| --------------- | --------------------------------------------------------------------------- | ------------------------------------------------ |
| 1. 計画         | パーツの一覧（標準パーツ・自由パーツ）、目・口の分け方、決めてほしいこと    | ユーザーの答え                                   |
| 2. 参照画像     | 元画像の白抜き版、パーツごとの拡大（8倍まで）、見本（表情など）があれば拡大 | `reference/zoom-*.png` と `authoring/zooms.json` |
| 3. 生成         | パーツごとに依頼。難しいパーツ（顔・目・口）は2枚作って選ぶ                 | `parts/<part>/<part>-vN.png` と記録              |
| 4. 配置         | パーツの種類ごとの方法で、倍率と位置を求める                                | `parts-aligned/<part>.png`                       |
| 5. 配置の確かめ | 全パーツでグリッド・輪郭の重ね・ずれの数値・全体の合成                      | 許容差の中（下の 5）。外れたら 3 か 4 へ戻る     |
| 6. 組み立て     | アセット・メッシュ・標準パーツ・かんたんセットアップ・目と口・揺れ          | `project.json`                                   |
| 7. 動きの設定   | 顔の向き・目の動き・髪（自動の設定と、まだ自動でない所の手順）              | 動きの確かめの条件                               |
| 8. 動きの確かめ | 細かい刻みの画像と測った数値                                                | ユーザーの見る所（下の 8）がすべて通る           |
| 9. 渡す         | README・計画の更新、画像を添えて報告                                        | —                                                |

## 2. 参照画像

- `reference/original-ref.png`: 元画像の透明な所の色を白にした版（透明度はそのまま）。どの表示でも同じに見える（`prepare_refs.py`）。
- **パーツごとの拡大:** パーツがいっぱいに入る、きつめの範囲（縦横比は 2:3・3:2・1:1）を切り出して拡大する（8倍まで。`tight_zooms.py`）。範囲と出力の大きさは `zooms.json` に書く。生成AIは、パーツが添付の大部分を占めるほど、位置と大きさを保つ。
- **見本の画像**（ユーザーがくれた、口を開けた絵など）があれば、元画像と同じ構図かを目・輪郭のずれで確かめ（ずれ 0px なら見本の座標をそのまま使える）、見本の拡大も作る。

## 3. 生成

依頼の文は `gen.py` の型を使う（`parts.json` の `style`）。どの型でも、毎回 Image 1 に元画像を付ける。

| 型           | 使う所                               | 依頼の要点                                                                                                          |
| ------------ | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| `edit`       | 元画像に見えているパーツ（ほとんど） | 「Image 2（元画像の拡大）を編集し、そのパーツだけを同じ位置・大きさで残し、ほかを透明にする。隠れた所は続きを描く」 |
| `zoomdraw`   | 元画像に無いパーツ（口の中・歯など） | 拡大の上に新しく描く。どこに・どの大きさで、を拡大の中の線（口の線など）を基準に書く                                |
| `editTarget` | 見本の画像にあるパーツ（丸い口など） | Image 2 は見本の拡大、Image 3 は見本の全体。見本を編集してそのパーツだけ残す                                        |
| `reference`  | 顔の向きの参考画像                   | 頭だけを回し、肩は動かさない。背景は白。左右それぞれ2枚作って選ぶ                                                   |

- **画風:** 「元画像の淡い水彩風のアニメ塗り・細い茶色の線。より写実的・鮮やか・細かくしない」を毎回書く（型に入っている）。
- **作り直し:** 合わなかったときは、`feedback.py` で前の輪郭（赤）と正しい形（緑の線）を描いた画像を付けて頼む。白目・まぶたは、正しい開きの緑の線を最初から付けると形が合う。
- **出力のばらつき:** 頼んだ大きさ（1024）と違う大きさ（1254 など）で返る。倍率も 0.5〜1.3 倍で変わる。配置は必ず測って決める（生成の位置をそのまま信じない）。
- **記録:** 依頼の文・添付・出力は `records/<part>.json` に残る。同じパーツを同時に2回頼むと版の番号がぶつかるので、同じパーツは順に頼む（ぶつかったら `split_parallel.py`）。

## 4. 配置

パーツの種類で方法を選ぶ。どれも縦横同じ倍率と平行移動（相似は小さな回転まで）。

| パーツ                                         | 方法                                                          | 道具                                   |
| ---------------------------------------------- | ------------------------------------------------------------- | -------------------------------------- |
| 元画像にはっきりした線がある（顔・髪・体・耳） | パーツの縁と元画像の線の距離が最小になる倍率と位置（chamfer） | `align.py --mode edges`                |
| 白目・目の開き                                 | 元画像で測った目の開きとの重なりが最大になる所                | `align.py --mode opening`              |
| 小さい色の部品（リボン・花・耳飾り）           | 元画像で色から測った形との Dice が最大になる所                | `colormatch.py`                        |
| はっきりした2点がある（結び目と花の中心など）  | 2点の対応から倍率と位置（必要なら 20° までの回転）            | `landmarks.py`・`accept_similarity.py` |
| 元画像に無い部品（口の中など）                 | 元画像で測った基準（口の線）からの位置と倍率                  | `accept_anchor.py`                     |
| 見本の形に合わせる部品（丸い口）               | 見本で測った形（外接矩形・輪の太さ）に合わせる                | `align_round_mouth.py`                 |
| 体の上下で比率が違う                           | 2つの倍率を高さでなめらかにつなぐ（例外。計画に記録）         | `accept_blend.py`                      |

## 5. 配置の確かめ

**全パーツで**行う。道具は `grid_check.py`。数値は `validation/placement.json`、元画像で読んだ目印は `validation/landmarks.json` に残る。

1. **全パーツの絵と目安（`grid_check.py --all`）:** パーツごとに `preview/grid-<part>.png` を書く。
   - 上の左: 元画像に 10px のマス目（50px ごとに太い線と座標）。上の中: 置いたパーツを半透明で重ね、輪郭を赤で描く。上の右: 元画像の線（青）とパーツの輪郭（赤。元画像で隠れている所は薄い赤）。ずれは青と赤の分かれで見える。
   - 下: パーツの目印ごとの拡大（1px のマス目）。目印は道具が決める。L 左端・R 右端・T 上端・B 下端（不透明な範囲の端の画素）、C 中心（重心）、M いちばん大きい塊の中心（ハイライトのように塊がいくつもあるとき）。
   - 目安の数値 `outlineToLine`: パーツの輪郭から、元画像のいちばん近い線までの距離の平均。元画像で見えている輪郭だけで測る（描く順は `authoring/composite.json`）。2.5px を超えたら `(check)` が付く。ずれている見込みが高いので、目印で特によく確かめる。線の無いパーツ（頬の赤み）、元画像に無いパーツ（口の中・丸い口）、ほとんど隠れているパーツ（体・首）も大きく出る。
2. **目印で測る:** 絵を見て、パーツの目印に当たる所を元画像で探し、その画素の座標を拡大のマス目で読む（マス目の線の右・下の画素が、その座標の画素）。元画像で隠れている目印と、元画像に無いパーツは飛ばす。読んだ座標を記録する。

   ```bash
   python -I tools/model-authoring/grid_check.py lowerLidR --orig L 422 329 --orig R 462 336
   ```

   目印のずれ（元画像 − パーツ）の最大を許容差と比べて `ok` か `off` を出し、絵に緑の十字を描く。2点以上あれば、直すときの倍率と移動（目印の重心のまわり）も出す。読み違えた目印は `--forget L` で消す。

3. **許容差:** 目・まぶた・眉・口は 1px、ほかは 2px。`off` のパーツは、出た倍率と移動で置き直す（4 の道具で `parts-aligned/<part>.png` を書き直す）か、生成からやり直す。置き直したら 1・2 をもう一度行う。
4. **輪郭の重ね（`overview.py`・`check.py`）:** パーツごとに「元画像の範囲｜パーツを重ねた絵（輪郭は赤）」を一覧にする。
5. **一致率:** 形のパーツは IoU・Dice（白目の開きで 0.9 前後）。
6. **全体の合成（`composite.py`）:** 全パーツを描く順に重ねて元画像と並べる。目・口・顔の輪郭・髪の外形を特に見る。

**このモデルで、ユーザーがあとから手で直したもの**（10/11 20:26 の版と比べた）を、グリッドで元画像と比べた:

| パーツ               | 手直し                                  | 元画像との比べ                                                                                                                          |
| -------------------- | --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 下まぶた R           | 位置 (+15.4, −7.3)                      | **配置の誤り。** 目安 4.36px で `(check)` が付き、絵で目の下の縁から離れているのが見える。直した位置を目印に入れると (+15, −7) で `off` |
| 耳 L・耳 R           | 大きさ ×0.91・×1.13〜1.2                | 元画像とは合っていた（耳 L は縁が元画像の線に乗る。耳 R はほとんど髪に隠れていて、元画像からは決まらない）                              |
| ハイライト L         | 位置 (+3.7, 0)・大きさ ×1.2             | 元画像とは合っていた（いちばん大きい塊 M が元画像のハイライトと重なる）                                                                 |
| 耳の後ろの髪         | 位置 (−12.7, +9.3)・横 ×0.81            | 元画像とは合っていた（外側の縁が元画像の線に乗る）                                                                                      |
| 跳ね毛 L・R          | 位置 (−34, −43)・(−2.5, −24)            | 元画像とは合っていた                                                                                                                    |
| 頭の変形・目の変形 L | 頭 8° 回転・(9.7, 2.0)、目 L −7.8° 回転 | 配置ではない                                                                                                                            |

元画像と合っていたのに直したもの（耳・ハイライト・髪）は、見た目か動きのための直しとみられ、配置の確かめでは防げない。意図が分かって決まりにできたら、ここに足す。

## 6. 組み立て

`projects/cardigan-bob-20261010/build.ts` の順（新しいキャラクターでは写して直す。ユーザーが直したあとは使わない）。

1. `parts-aligned/*.png` から、アセット（不透明な範囲で切り出し）とメッシュを作る。目と口は 5px 間隔の細かいメッシュ（瞬き・口の線に沿って閉じるため）。
2. 標準パーツ・自由パーツに割り当てる。描く順は元画像の重なりに合わせる（耳が前髪の手前に見える、など）。
3. かんたんセットアップ（顔の向きは `head-pose`）。
4. 目: 開き × 笑い目の格子のキー。上まぶたの下の縁と白目の上の縁を同じだけ動かし、閉じると白目は線になって消える。閉じた目じりは折り返さず、先細りの直線。
5. 口: 閉じた口は元画像の細い線とつやだけ（肌色の唇の板は継ぎ目が残るので使わない）。丸い口は `round_mouth.ts`（見本の丸へ開き、閉じた線は開き始めに縁の線と入れ替わる）。
6. 揺れ（軸揺れ・流れ揺れ・胸揺れ）。
7. 確かめ用の姿勢（`validation/closeup-poses.json`）と画像を書く。

## 7. 動きの設定（顔の向き・目の動き・髪）

- **今の自動:** かんたんセットアップの `head-pose`。輪郭・あごが動かず、目鼻口だけが横にずれる（I-067）。
- **今の手順（CL の試作）:** 左右を向いた参考画像を各2枚生成して選ぶ → 肩で位置を合わせる（`ref_align.py`）→ 特徴点とあごの線で対応を取る（`turnref.py`）→ 層ごとの動きの場を当てはめる（`turnfit.py`）→ 近い側の目が ±30 で「顔の幅 × 12%」動くように量をそろえる → 頂点のキーにする。
- **それでもユーザーが手で直した所:** 目の遠近・耳の大きさ・前髪と後ろ髪・横髪・首・視線の幅・笑い目の弧。直し方を型にまとめ（ワープ W1〜W6、変形のキー T1〜T8）、自動にする規則（A2・A3・A8〜A13・A15）を [I-067 の計画の「手で直した所の体系」](../../docs/i-067-face-turn-plan.md)に書いた。自動になるまでは、その型と量（顔の幅・目の幅・白目の大きさに対する割合）に合わせて、この段で手で設定する。キーは 0 と ±30 だけにする（中間のキーは直しにくい）。上下（FaceAngleY）の髪の動きは、髪の長さごとの資料がそろうまで自動にしない（[I-091](../../docs/issues.md)）。それまでは計画の上下の表の量を目安に手で設定する。

## 8. 動きの確かめ

ユーザーが見る所（どれも細かい刻みで、顔を ±30 に向けた姿勢でも確かめる）:

- 瞬き: 上まぶたの下の縁と白目の上の縁が、どの開きでも離れない。閉じたとき白目が見えない。閉じた目じりは直線。
- 口: 開け閉めで線や継ぎ目が残らない。口の中が縁の外へはみ出さない。
- 顔の向き: 輪郭・あご・頬の縁も動く（目鼻口だけが動くのは不可）。横髪・耳が顔から離れない。
- 輪郭の編集: 段々（Z 字）に折れない（輪郭線のツールで、線に沿って頂点を足してから動かす）。

道具:

- `raster.py eyes|mouth|round`: 確かめ用の姿勢を描き、数値（白目の見えている量、線の残り、はみ出し）を `validation/` に書く。
- アプリの描画で確かめる: 開発サーバーを起動し（ロックを取る）、ヘッドレスの Edge（Playwright の `channel: 'msedge'`）で `window.__studio` からプロジェクトを読み込み、姿勢ごとに撮る（例: `.cache/round-mouth-shot.mjs`）。アプリの画面の小窓では、描き直しが止まって撮れないことがある。
- 元画像との並べ（`preview/compare-original.png`）、姿勢の一覧（`preview/face-contact-sheet.png` など）。

## 9. 渡す

- `projects/<id>/README.md` と `modeling-plan.md` に、決めたこと・変えたこと・確かめた数値・画像の場所を書く。
- 手順や道具を変えたら、このファイルを直す（CL・CO の共有の資産）。
