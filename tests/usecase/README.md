# ユースケーステスト（画面での手の確認）

アプリの全機能が画面の上で使えるかを、人が手で確かめるための管理表。自動テスト（`pnpm test`・`pnpm e2e`）とは別に、実際の画面をユースケース（使う人の目的に沿った一連の操作）の順に操作して確かめる。

## ファイル

| ファイル                         | 中身                                                                                                                                      |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| [usecases.md](usecases.md)       | ユースケースの一覧（UC-xx）。手順・期待する結果・回収する確認点・結果を書く欄                                                             |
| [checkpoints.md](checkpoints.md) | 確認点の一覧（CP-xxx）。設計書（files/implementation-steps-all.md）から取った「できているべき点」。どのユースケースで確かめるか・結果の欄 |
| [changes.md](changes.md)         | 途中変更の確認。設計書から変えた点・直した課題の確認点（CH-xxx）と、それを確かめるユースケース（UC-CH-xx）                                |

件数（2026-10-05 に作成）: ユースケース 39件（UC-01〜39）で確認点 349件（MVP 120・STEP1 150・STEP2 79）をすべて回収する。途中変更はユースケース 16件（UC-CH-01〜16）で確認点 105件を回収する。確認に使う素材（サンプルの PSD、基準モデルの写し、警告用・差し替え用の PSD など）は、usecases.md と changes.md の頭の「用意するもの」「手順で使う素材」にある。

## 使い方

1. アプリを起動する（デスクトップの「2D Live Model Creator Studio」。作り直すときは `pnpm app:install`）。
2. [usecases.md](usecases.md) のユースケースを上から順に行う。各ユースケースの「前提」をそろえてから手順を進め、期待する結果と比べる。
3. ユースケースの「結果」に記号を書く。うまくいかなかった確認点は [checkpoints.md](checkpoints.md) の「結果」にも書き、「メモ」に何が起きたかを書く。
4. 途中変更は [changes.md](changes.md) を同じように行う（設計書どおりではなく、変えたあとの動きを確かめる）。
5. NG が出たら、内容を docs/issues.md の課題にする（番号をメモに書く）。

## 結果の記号

| 記号   | 意味                                                                |
| ------ | ------------------------------------------------------------------- |
| （空） | まだ確かめていない                                                  |
| OK     | 期待どおり                                                          |
| NG     | 期待と違う（メモに内容、課題の番号）                                |
| 保留   | 確かめられなかった（機器が無い・前提がそろわない など。メモに理由） |
| 対象外 | この PC・この版では確かめない（メモに理由）                         |

## 書き方の約束

- 結果を書くときは「日付・確かめた人・PC」をユースケースの「メモ」に書く（例: `2026-10-06 （名前） RTX 4050 のノート`）。
- 「要るもの」の欄は、その確認に必要な機器や素材（カメラ・マイク・OBS・Spout2 のプラグイン・Photoshop の PSD・基準PC など）。そろわないときは「保留」にする。
- 確認点の「根拠」は設計書の行番号（L1234）。設計書を変えたときは、確認点も合わせて直す。
