# かんたん（表示の段階）を廃止する（設計）

2026-10-12 CL。ユーザーの要望（課題は I-088）。2026-10-12 CO: 次の実装指示を受け、推奨D1〜D5=A・D6=Bで実装する。実際の契約番号はCC-019。以下は設計時点の調査と選択肢の記録。

## 実装で決めたこと

表示段階の型・設定・登録条件を外し、詳細項目を常に表示する。古い設定のuiLevelは無視する。手動で追加・編集したキーは常にロックし、明示的な解除の操作を維持する。自動セットアップの処理を保ち、名前を［自動セットアップ］に統一する。

方向グリッドと任意の組み合わせは、組み合わせの補正の節で選ぶ。同じ補正キーの操作を二重に出さず、選択したグリッドからキーの編集・ロック・自動に戻す操作へ進める。表示段階の切り替えは不要。

## 解決したいこと

ユーザーの言葉:

> かんたん機能はあまり使いどころがないので、いったん廃止してもいい。

このアプリで「かんたん」と付くものは2つある。どちらを指すかで、変更の大きさがまったく違う（D1）。

| もの                              | 中身                                                                                                                                                               | 廃止したときの影響                                                                                                                   |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| A: ヘッダーの［かんたん］［詳細］ | 表示の段階。モードごとに、かんたんでは一部のツール・節・項目を隠すか「▸ 詳細」の中にしまう（カード26・27）                                                         | 画面の出し分けをやめ、すべて今の「詳細」の表示にする。枠（shell）・保存の形・約 33 のテストに関わるが、モデルの作りには関わらない    |
| B: かんたんセットアップ           | 標準パーツの割り当てから、階層・回転の中心・描く順・マスク・奥行き・パラメータ・まばたき・口・顔の向き・呼吸・胸揺れなどのキーを自動で作る（カード11・42・53・98） | モデルの動きを自動で作る唯一の手段が無くなる。閉じた目の線・顔の向きの直し（I-067）・MVP の受け入れ条件・主な e2e が成り立たなくなる |

「使いどころがない」「いったん」という言葉と影響の大きさから、この設計は **A（表示の段階）を廃止する** 前提で書く。B を指していた場合は、別に設計し直す。

## 今の作り（A。コードで確かめたこと）

- 値: `UiLevel = 'easy' | 'detail'`、モードごと。既定はすべて「かんたん」。`Environment.uiLevel`（environment.json）と `EditorState.uiLevel` の両方に持つ。
- ヘッダーの［かんたん］［詳細］（`shell/level/UiLevelToggle.tsx`）。パネル・節・ツールの登録の `level`（`'easy' | 'detail' | 'both'`）で出し分ける（`shell/registry.ts` の `visibleAt`）。項目ごとの「▸ 詳細」（`shell/DetailDisclosure.tsx`）。

かんたんと詳細で違うもの:

| 場所                                                                                       | かんたん                                         | 詳細                           |
| ------------------------------------------------------------------------------------------ | ------------------------------------------------ | ------------------------------ |
| ワープのツールとパレット                                                                   | 出ない                                           | 出る                           |
| パラメータの生成方式                                                                       | 出ない                                           | 出る                           |
| 組み合わせの補正（2つのパラメータ）                                                        | 出ない。代わりに「方向グリッド」を出す           | 出る。方向グリッドは出ない     |
| マスクの選び方                                                                             | マスク元を1つ選ぶ欄。複数・反転は「▸ 詳細」      | 複数のマスク元のチェックと反転 |
| トラッキングの割り当て（スタジオ）                                                         | 出ない                                           | 出る                           |
| 動きの数値・物理の数値・合成方法・カードの押し方・フェードの秒数・影響範囲・遷移の詳細など | 「▸ 詳細」の中                                   | そのまま出る                   |
| **キーを手で直したとき**                                                                   | **ロックする**（`services/keyEditor/common.ts`） | ロックしない                   |

最後の行は表示ではなく動きの違い。かんたん（既定）では、手で直したキー・足したキーをロックするので、［奥行きで作り直す］や生成方式の「曲面」でも消えない。詳細では、手で直したキーも、ロックしていなければ作り直される。

## 考え方

- ヘッダーの［かんたん］［詳細］を外し、どのモードも今の「詳細」の表示にする（D2）。
- 「▸ 詳細」の中にしまっていた項目は、そのまま出す（D3）。
- かんたんだけのものの扱い（D4）:
  - 方向グリッド（組み合わせの補正のかんたん版）: 組み合わせの補正の節に「方向グリッド」の表示を入れて残す。
  - マスク元を1つ選ぶ欄: 外す（複数のチェックで同じことができる）。
- 手で直したキーのロック（D5）: 今の既定（かんたん）と同じく、手で直したキー・足したキーはロックする。直したキーが作り直しで消えないため。ロックを外したいときは、今と同じく印の右クリックで外す。
- 保存の形: `Environment.uiLevel`・`EditorState.uiLevel`・登録の `level` を消す。古い environment.json に `uiLevel` があっても、読み込みで無視するだけ（今の読み込みは、知らない項目を捨てる）。
- 契約の変更（CC-020）: `UiLevel`・`Environment.uiLevel`・`EditorState.uiLevel`・`PanelDef.level`・`SectionDef.level`・`CanvasTool.level`・`DetailDisclosure` を消す。

## テストと確認

- 単体・e2e のすべてが通ること（切り替えのテストは消し、出し分けのテストは「いつも出る」に直す）。
- 画面: 開発サーバーで 1440×1000・800×600 の各モード。ヘッダーに切り替えが無いこと、ワープ・生成方式・トラッキングの割り当てが出ること、組み合わせの補正の節で方向グリッドを使えること。
- 古い environment.json（uiLevel あり）で起動できること。

## 完成の条件

- 手で直したキーは、今と同じく作り直しで消えない。
- かんたんセットアップ（B）は今のまま使える。
