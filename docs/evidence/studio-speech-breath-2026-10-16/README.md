# 終了時の自動解放と、吐息を含む演技の試作（2026-10-16）

アプリへ反映した変更は**終了時の自動解放**。CosyVoiceの比較音声は**入力した台詞と出力の不一致が判明した失敗例**で、通常の読み上げには未統合。呼吸表現の出来を評価できる音声としては扱わない。

## アプリ終了時の自動解放

メイン画面の破棄時に、別入力窓・映像出力窓が残っていてもアプリ全体を終了する。専用音声プロセスを終了し、終了中の要求から音声ホストを再起動しない。実行環境設定の変更時は、従来通り再接続可能。別入力窓だけを閉じる操作は送信済み発話を止めない。

検証用Tauriアプリで、別入力窓から入力→先行合成完了→常駐`speech_worker.py`を含む子プロセスのPID・作成時刻を記録→メイン画面だけを閉じた。アプリの終了コードは0、記録したプロセスの残存は0件。[記録](shutdown.json)。GPUモデルが常駐した条件で確認し、明示の解放操作はしていない。

`speechShutdown.e2e.ts` 1件、TypeScript型検査、Rust整形、画面コード整形、本番ビルド、`git diff --check`が成功。本番の検証用フックがないことを確認。通常のインストール先へ反映し、実行ファイルと音声資源の計12ファイルのSHA-256を照合した。[配置照合](installed.json)。

## 演技についての要件修正

求められているのは音節の反復や無音の挿入ではなく、弱い声の立ち上がり、語尾の減衰から息への移行、息継ぎと再開の一続きの演技。冒頭の「ぁっ」を普通の発音で読ませる試作に対し、ユーザーから「ぁあっに聞こえる、ほとんど吐息でよい」と修正を受けた。

全試作の参照は既存の架空話者`original-soft-girl.wav`、SHA-256 `dac5a689fe406465a88b481d085ae4fa0396adc9baeda044c93913df39ed039d`。参照の固定は同一の声が知覚されることの保証とは別で、試聴による評価が必要。

### ブレス指定に対応するCosyVoice3での比較

[公式モデルカード](https://huggingface.co/FunAudioLLM/Fun-CosyVoice3-0.5B-2512)は日本語、参照声による合成、`[breath]`を含む制御を示す。[公式トークナイザー](https://github.com/QwenAudio/CosyVoice/blob/074ca6dc9e80a2f424f1f74b48bdd7d3fea531cc/cosyvoice/tokenizer/tokenizer.py)の`[breath]`・`[quick_breath]`を使い、冒頭に「あ」の文字を入れず試作した。

- ソース `074ca6dc9e80a2f424f1f74b48bdd7d3fea531cc`、モデル `29e01c4e8d000f4bcd70751be16fa94bf3d85a18`に固定し、取得した重みを公式LFSのSHA-256と照合。既存のアプリ環境を変更せず`.cache/cosyvoice-breath`に隔離。
- 標準のFP32重み・22秒の参照特徴ではこの6GB GPUで処理が重く、比較を中断。LLM・FlowをFP16にし、音響参照特徴は先頭6秒、話者の埋め込みは参照全体から一度だけ作ったものを共有。HiFTはFP32重みと公式の自動混合精度。モデル構成は公式のまま、学習用設定だけ読み込み対象から外した。[実行環境](cosy-runtime.json)。
- 公式の逐次処理は`token_hop_len`を要求間でも増やすため、各発話の開始時に設定値25へ戻した。戻さない条件は、後続の最初のPCMまで約7.3秒かかる。[比較](cosy-unreset-hop.json)。

| --- | ---: | ---: | ---: |
| 通常文 | 4.80秒 | 7.62秒 | 3.74秒 |
| 冒頭を吐息にした表記 | 13.60秒 | 17.16秒 | 2.09秒 |

[通常文](cosy-neutral.wav)・[冒頭の吐息](cosy-breath.wav)・[敬体](cosy-faithful.wav)、[測定](cosy.json)。数値は生成までで、アプリの入力→実音声出力ではない。モデル読み込みは約21秒で表の外。最大割当約3544MiBは読み込み時も含む。Qwenとの表記・生成モデル・発話長の異なる比較で、単純な速度改善とは扱わない。

[CAMPPlusによる参照声との補助比較](speaker-comparison.json)は、Qwenの表記試作0.895、CosyVoiceの吐息試作0.824。指標は呼吸・演技にも影響され、声が変わって聞こえないことを保証しない。減衰や吐息の自然さも数値だけで合格にしていない。

ユーザーから「『あ、あなたのことが～』を聞けると思ったが、そうではない」と内容不一致の指摘を受けた。ファイルのSHA-256は生成結果と提示したWAVで一致し、別音声のリンクではなかった。保存した要求文には日本語の対象文が入っているが、出力がその内容を保持していない。

既存のWhisper-small固定版をCPUで使い、期待する文や言語のヒントを認識器へ渡さず、提示したWAVそのものを検査した。[台詞の確認結果](content-check.json)、[期待する台詞](content-cases.json)。Qwenの従来音声は「あ、あなたのことが、だ、大好きです。」、表記試作も「あなたのことがだっ大好き」と認識されて一致。一方、CosyVoiceの通常文・ブレス・敬体の3件すべてが不一致となり、通常文から既に崩れている。中国語の文字列や反復として認識された内容は実際の発話の正しい書き起こしと断定しないが、日本語の対象文と一致する証拠にはならない。

原因の切り分けで、試作環境がQwen用のTransformers 4.57.3／Tokenizers 0.22.2を引き継いでおり、CosyVoiceの指定するTransformers 4.51.3と異なることが判明した。日本語をトークン化して戻すと元文と完全一致し、軽量化・逐次復号を外したFP32・全文復号でも入力と異なる音声が出た。[変更前の通常文と参照文付きの検査](content-probe.json)。元の日本語が別の文へ書き換えられたのではない。

モデル・原文・FP32・全文復号を保ち、隔離環境だけをTransformers 4.51.3／Tokenizers 0.21.4へ変更すると、通常文は「あなたのことが大好きです」と一致した。[変更後の検査](content-probe-official-transformers.json)、[生成時の条件](content-probe-official-generation.json)。アプリが使うQwen環境は4.57.3／0.22.2のままで、変更していない。試作セットアップにも版を固定し、修正した試作スクリプトは異なる版で実行するとモデル読み込み前に停止する。[版確認付き試作](corrected-cosy-audition.py)。依存ライブラリの組合せによる互換性問題を確認したが、内部のどの演算・API差が発話崩壊を起こすかまでは特定していない。

同じ認識環境で修正前と修正後のWAVを再検査した。[比較](content-comparison.json)。修正前の無関係な発話は引き続き不一致、従来Qwenの「あ、あなたのことが、だ、大好きです」は一致。版修正後の演技付き試作にも「あなたのことかな？大好き」等の認識上のずれが残り、台詞一致の検査は通過していない。通常文の復旧を、演技付きの完成とは扱わない。修正後の音声も、比較用の合格音声としては提示しない。

合成器そのものを不採用と決める判断と、今回の試作構成の不具合は区別する。一般入力の演技への変換、アプリ内の切替・キャンセル・先行生成への統合は未実施。

再発防止として`tools/voice-engine/tests/check_speech_content.py`を追加した。ローカルの認識モデル・文字変換部品・WAVと期待する台詞の一覧を明示し、認識後にのみ台詞を照合する。句読点・表記幅以外の語句は勝手に除かず、不一致で終了コード1を返す。今回の実音声5件で一致2件・不一致3件を区別した。これは開発用の試作確認で、通常の生成経路へ追加する認識処理ではない。認識の一致は息の自然さ・声の同一性の合格を意味しない。

既存のPython回帰検証101件も成功。音声デバイスへの出力・アプリの再導入はこの内容検査では行わず、実験終了後の専用合成プロセスは0件、GPU使用は360MiBに戻った。
