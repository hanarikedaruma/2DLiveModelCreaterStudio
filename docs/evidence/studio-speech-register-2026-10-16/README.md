# 読み上げ途中の低音化と声質の崩れ

2026-10-16。「みんなのことがすきです」を繰り返すと、途中だけ声が極端に低くなる報告を調査した。同じ参照声、seed、文を使い、直前3件が同じ文になった条件で再現した。

## 原因と修正

生成した16コードの音声データを640msずつ波形に戻す際、過去25フレームだけを毎回付けてデコーダーを再実行していた。これでは、8層の注意機構と因果畳み込みが持つ過去の状態が失われる。同じコードをまとめて復号した波形にはない、声の低下や声質の変化が生じていた。全文再生方式も内部ではこの経路で先行合成するため、両方式が対象だった。

`speech_decoder.py` で、注意機構のKV、畳み込みの入力履歴、転置畳み込みの重なりを連続保持するよう変更した。参照音声の全コードから一度だけ準備し、その状態の独立した複製を発話ごとに使う。注意機構の保持は各層71フレーム、畳み込みは各カーネルに必要な長さのみで、長い発話でも状態が増え続けない。中断・例外では元のメソッドへ戻す。

モデル、話者プロンプト、サンプリング設定、声質設定、出力フィルタは変更していない。音声の高さを後から引き上げる処理も追加していない。元のモデルが生成したコードを連続した波形に復元する修正。

## 同じコードによる比較

再現したコードを固定した回帰データにし、生成の偶然性を除いて比較した。参照279フレーム、対象28フレーム（2.24秒）。ピッチはlibrosa pYINで推定し、有声確率・音量で無声区間を除外した。140Hzはこの架空声の再現試験に使う比較基準で、製品の音程制限ではない。

| 指標 | 修正前の分割復号 | 全コードをまとめて復号 | 修正後の分割復号 |
| --- | ---: | ---: | ---: |
| 有声区間の最低推定ピッチ | 123.47Hz | 207.65Hz | 207.65Hz |
| 140Hz未満の区間 | 50ms | 0ms | 0ms |
| 推定ピッチ中央値 | 261.63Hz | 270.85Hz | 270.85Hz |
| 全コード復号との波形相関 | — | 1 | 0.999976 |

不規則な1/3/11/2/7/4フレームの分割でも最低推定207.65Hz、波形相関0.999975だった。BF16の分割サイズによる丸めの違いがあるため、全コード復号とのビット一致とは扱わない。繰り返しと中断後の同一条件での再実行は、それぞれFloat32 PCMが完全一致した。参照の準備は初回のみ約0.30秒。

[全データ](decoder.json)、[修正前の音声](before.wav)、[修正後の音声](after.wav)、[全コード復号の音声](whole.wav)。音声はモデルの復号結果で、音声変換側のフィルタを適用する前の比較データ。

## 検証と配置

Python82件、e2eの型・lint・整形、実GPUのTauri結合3件が成功した。実アプリで対象文を5回繰り返し、最初の3回は全文、最後の2回は逐次で再生した。全て同じ参照声、状態保持した復号、エラーなし。直前3件が同じになった最後の2回はフレーム数も一致し、再バッファは0回だった。

通常の2文章でも入力直後に送信し、入力開始から実WASAPIのDAC出力開始は1.818秒／1.769秒、再バッファ0回。先行合成・IME・古い入力の中断と引継ぎも通過した。実アプリはMuteで検証し、区間内のピッチと波形は前掲の実GPU回帰試験で測定した。

[実アプリの5回繰り返し](native-repeated.json)、[出力開始](native-latency.json)、[先行合成と固定話者](native-draft.json)。ユーザー用Studioと読み上げワーカーが終了していることを読み取りで確認してから、修正した音声処理を既存のインストール先へ反映した。画面・Rust側の変更はなく、既存の本番実行ファイルを使う。[配置hash](installed.json)を照合した。ユーザーのアプリを終了する操作は行っていない。

## 再現手順

読み上げ用Pythonで次を実行する。音声機器を開かず、固定データを使って実GPUで比較し、繰り返し・中断・状態の上限も検証する。

```powershell
python tools/voice-engine/tests/check_speech_decoder.py --cache <モデルキャッシュ> --output <結果フォルダ>
```

回帰データは `tools/voice-engine/tests/fixtures/speech-pitch-codes.json`。モデルと参照WAVのhashも記録してある。畳み込みの分割不変性・バイアス・例外時の復元は `test_speech_decoder.py`、実アプリは `apps/desktop/e2e/speechDraft.e2e.ts`。

固定版の構成は `speech-stream-source.json`、比較対象の上流実装は [Qwen公式の音声デコーダー](https://github.com/QwenLM/Qwen3-TTS/blob/main/qwen_tts/core/tokenizer_12hz/modeling_qwen3_tts_tokenizer_v2.py)。単発の話者特徴の類似度や参照声のhashだけでは、分割復号による区間内の声質の崩れを検出できなかったため、実際のコード・波形・途中のピッチを比較する試験を追加した。
