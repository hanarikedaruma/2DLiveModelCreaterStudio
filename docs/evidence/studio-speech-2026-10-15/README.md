# スタジオのチャット読み上げ

2026-10-15 CO。liverVoiceChanger 0.9.0のローカル読み上げをStudioへ統合した。[使い方](../../studio-speech-guide.md)。

## 実装

- スタジオ右側の専用パネルに、300文字までの入力欄、Ctrl＋Enter送信、停止、ライブMute、出力機器、場面・読み方・声の説明、履歴を用意した。日本語入力の確定とEnterだけでは送信しない。
- 日本語の全文は `text`、声・読み方・場面・直前3件の発話は `instruct` に分ける。入力文を発話し、自動の返事を作らない。外部通信を使わず固定版Qwen3-TTS VoiceDesignを再利用する。
- 音声出力だけのWASAPIストリームでマイクを開かない。最終出力PCMをDAC時刻とともに既存の口の解析へ送る。Mute・停止・エラーでは口を閉じる。
- WindowsのCOM、音声ストリーム、audio mutexの開始・終了を同じ専用スレッドで行う。生成停止では自身のworkerと子プロセスを終了し、GPUと一時データを解放する。
- 読み上げ設定はプロジェクトへ保存し、下書き・発話履歴・生成音声は次回へ保存しない。履歴は最大20件、文脈は直前3件。プロジェクト切替で履歴を消す。保存形式11の任意項目として追加した。

## 実機

関連するデスクトップ57件、保存形式・再生時刻ルーター11件、Python62件が成功した。TypeScriptのアプリ・e2eの型検査と変更箇所のESLintも成功した。COM・ストリーム・mutexが同じ専用スレッドで開始・終了する回帰テストを含む。

`.cache/locks/main.lock` を取得し、別の識別子 `jp.co.globalsystems.live2dstudio.speech-verification-20261015` のアプリと、基準モデルの写しで検証した。制作プロジェクトと元アプリは変更していない。

[実GPU・WASAPI結果](native-speech.json): 初回読み込み17.28秒、生成12.90秒、音声3.12秒、最大VRAM約4087MiB。マイク未選択のまま312窓を受信し、有限値・再生時刻の単調増加を確認。実デバイスはSound Blaster Play! 3、Muteの非ゼロ出力0。生成した言葉だけが履歴へ追加され、モデルの常駐を確認した。

[生成の途中停止](cancel-speech.json): 停止90.4ms、停止後の再生通知0、モデル解放、一時要求・一時WAVの削除を確認。発話履歴のクリア、設定の保存と再読込も成功した。Tauri結合2件成功、pageerrorなし。

[960×600](speech-960.png)と[1440×900](speech-1440.png)で表示を確認し、入力パネルの横方向のはみ出しが無いことを測定した。

最初の実機検証では、非同期のMuteを押した際のチェック表示の戻りと、COM未初期化のスレッドでのWASAPI開始エラーを検出した。Muteの即時反映・失敗時の復元、音声の専用所有スレッドを追加し、再検証で解消した。合成波形1秒の単独Mute出力でも100窓・非ゼロ0・エラーなし、終了後の音声mutex再取得を確認した。

通常の識別子・VITE_E2Eなしの本番ビルドを既存のインストール先へ配置した。[配置後のSHA256](installed-hashes.json)で、実行ファイル・読み上げコード・Studioのブリッジの一致を確認した。起動中のユーザーのアプリを終了していない。

## 確認の範囲

文脈指示へのルーティングと全文の保持は単体テストで確認した。意味に合う感情・抑揚の自然さ、読み間違い、参照WAVとの声の一致はこのMute試験では評価しない。声は自然言語の説明から合成するため、マイク変換と同じ声を保証しない。実際のOBS・仮想デバイスを含む配信経路は、利用する機器で試聴し同期を調整する。
