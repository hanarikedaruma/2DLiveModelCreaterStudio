# I-087 パネルのリサイズの実装と検証

2026-10-12 CO。続きの実装指示を受け、[計画](../../issue-backlog-plan.md)のI-087を実装した。[採用仕様](../../panel-resize-design.md)。契約とProject・Environment・schemaVersionは変更していない。

## できること

- モデリング・アニメーション・スタジオの左右の列幅、左と右の各パネルの高さ、オブジェクトパレットの高さを変更できる。
- スタジオの下の列の高さと、横に並ぶパネルの幅を変更できる。
- アニメーションのタイムラインの高さ、スライダーの幅を変更できる。狭い画面では上下に並び、スライダーの高さを別に覚える。
- ドラッグ中は表示だけを変え、離すと保存する。Esc・pointercancel・フォーカス喪失・モード切替・窓の制約変更では取り消す。矢印キーで16px、Shiftで64px。ダブルクリックでその境目を戻す。
- ☰ の［パネルの配置を元に戻す］で全モードのサイズを戻す。たたみの記録は残す。
- 旧`panelHeights`を移行し、サイズは`layoutSizes`で一元管理する。他の列やモードの記録を上書きしない。窓を縮めたときは表示だけを調整し、広げると記録した幅へ戻る。

## 本物のTauri／WebView2

`.cache/locks/main.lock`を取得してデバッグビルドと検証を実施。検証時だけ識別子を`jp.co.globalsystems.live2dstudio.verification-i087-20261012`にし、利用者とは別の設定・自動保存・WebViewのプロファイルを使用した。利用者の起動中のアプリは閉じていない。

[結果JSON](native.json)。1440×1000・960×600の論理サイズで、全3モードの実ドラッグ、Esc、保存、メニューリセットとたたみの保持を確認した。各サイズの検証後にプロセスを終了して起動し直し、すべてのモードのサイズが残ることを確認した（計2回の再起動）。中央は最低320×200pxを保ち、DPI125%の描画解像度も追従した。各リサイズ操作の前後で作品のJSONが不変だった。pageerrorは0。
