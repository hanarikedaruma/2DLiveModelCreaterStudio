## 調整と制約

- 読点だけでは「う、うん」が一続きの「うーん」になり、空白だけを足すと後半の「うん」が欠ける合成も確認した。最終版は合成する演技だけを「うっ。うん。」にして、冒頭と本文を残す。入力本文・履歴は「う、うん。」のまま。新しい語や別の話者は加えない。他の3例には読点後の空白を補う。
- 初期PCMが短く終わる場合は通常の640ms内で処理する。「い」のように言い出しが遅く区間をまたぐ場合に限り320msずつ追加確認し、最大1280msで打ち切る。今回の「い」は960msで確定し、最初のPCMまで1.264秒、他3件は約0.85〜0.88秒だった。先行生成が未完了の場合に待ちが増える条件で、追加の音声合成モデルを呼ぶ時間ではない。
- 70〜320msの音と80ms以上の間、音量の谷・再上昇、響きの安定性を確認する。判断できないときは元の音を保つ。追加確認したPCMも従来の640ms以下の送信単位へ戻し、終了・中断で欠けたり残ったりしない。
- 本文PCMが一致しても、合成器自身による語の省略を検出できるとは限らないため、開発用試験では対象音より後にも音声が残ることを検査する。最終4件は本文の活動区間が360／270／760／500msあり、すべて元の本文と完全一致。[本文の測定](final/body-pcm.json)。
- 独立したWhisper-smallによる全文の自動照合では、息が「ひっ」「へぇ」「ふっ」等として文字になり、極短い「うん」の言語判定も不安定だった。本文だけを日本語指定で検査すると「行きます」「ええんですか」「おっきい」は一致し、「うん」は「ん？」と認識されたため、**全件の厳密な認識一致とは扱わない**。認識器へ期待文は渡していない。[最終本文の検査・日本語指定を明記](final/body-content-ja.json)。元と処理後の本文一致の証明と、発音・演技の聴感評価は別。
- このフォルダ直下のWAVと`content-check.json`・`body-content-check.json`は空白だけの候補の失敗記録。後半が欠けた「う」は採用していない。最終版は`final/`に分離した。
