## 実装

- Seed-VC Tiny / 大型、WASAPI入出力、開始・停止・Mute・時刻を合わせたBypass。
- 声質3項目、雑音対策、5種類・最大8個のフィルタ、実行中の変更、声・フィルタ設定の保存と移行。
- 独自参照WAVのhash管理・プロジェクトへのコピー、目標声の試聴、WAV比較・中断・完成後のファイル確定。
- 最終出力PCMのDAC時刻をTauri Channelへ渡し、描画時刻の波形を口に適用。無音・Mute・停止では閉じ、母音を推定できない発話は音量の開閉へ戻す。
- 音声セッションをパネルの寿命から分離。開始・停止の直列化、準備中の取消、古い接続の無効化、自身のプロセスと子の終了。
- 保存形式11。未設定の旧モデルはAI音声OFF。既存のモデル・口形・キーを移行で変更しない。

## 連続試験で変更した点

対象PCはRTX 4050 Laptop 6GB / Ryzen 7 7735HS。マイクのPCMを既存の公開JVS音声・合成雑音・無音に置き換え、実WASAPI機器の時計で処理する。出力は常にMute。利用者の録音や公開検証音源を配布物へ入れない。

180ms・240msの短い区間は、初期の実機試験で不足が発生した。標準は4ステップ/400ms、生成履歴200ms、開始時の余裕240msとした。CPUを1スレッドに制限し、Tinyの待ち時間には軽いCUDA処理を間欠実行する。GPU全体の設定は変更しない。標準の既存測定の内部遅延は約1.2秒で、当初計画の「約0.56秒から50ms以内」の目標は未達。

推論時間だけでは、送受信・準備・スケジュールによる遅れを捉えられないため、音声の往復時間、制御時間、雑音処理・推論・後処理の内訳を記録した。短いパイプ書込みも最後まで送る。失敗した試験も `.cache/voice-evidence/` に残している。循環GCを止める案は改善の確認ができず採用していない。

CPU制限・CUDAの間欠処理を含む75秒の単体試験では、7回のフィルタ・声質変更、7,501窓、音声の不足・overflow・入出力status 0、最大音声往復約305ms、VRAM約1,146MiB、内部遅延約1.21秒。

最終の[30分試験](live-30min.json)は成功。1,800.002秒、179,994窓、180回の声質・フィルタ変更を行い、不足・overflow・入出力statusはすべて0。最大音声往復485.93ms、VRAM1,146.14MiB、終了時の推定内部遅延1,208.10ms。フィルタ全体OFF・8個・順序反転・標準を繰り返した。開始は約14.45秒。受信時刻の値は音声コールバックから単体検証へのものなので、IPC遅延とは扱わない。

[workerのメモリ](worker-memory.jsonl)は、今回の待機処理を含むworkerで14:03に1,301.7MiB、14:18に910.1MiB。Windowsのworking setの2点測定であり、メモリリークが無いという一般的な証明にはしない。

## この確認の限界

単体のMute試験は、相手への通話遅延、OBS・ゲームを含む全経路、本人の声の聴感、母音の目視による品質判定を確認するものではない。音声の再生時計と口のスケジュールを合わせる実装はあるが、実際の配信では仮想デバイスとOBS側の遅延も確認し、同期微調整を使う。

VoiceDesignによる新しい参照WAVの生成は計画の任意段階V6に残す。公開配布ではGPL等の条件と対応ソースの提供方法を確認する。今回の作業はこのPCへの統合と検証。
