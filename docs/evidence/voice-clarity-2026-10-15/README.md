# 小さい声・発話再開時の音割れへの対応

後続の修正: 実RNNoise DLLの20ms遅延を10msとして混ぜていた不具合を確認し、元PCMとの時間合わせを修正した。以下はその修正前の検証。[現行版の測定と制約](../voice-articulation-2026-10-15/README.md)。

2026-10-15 CO。統合後Studioの［マイク・音声］で、バランス品質でも音程変化時の電子感が残る、小さくゆっくり話すと言葉にならない、無音から話すたびに最初の一文字が大きく割れる、という報告への修正。本人の音声を録音せず、公開音声・合成波形・Muteの実機試験を使った。

## 変更と根拠

- 入力メーターが入力ゲイン適用前だった。`inputGainPeak`へ変更し、ゲイン調整後の過大入力を表示する。これ自体は入力音量を変えない。
- 小さく低速にした公開音声では、VADのマスクが発話の一部を消した。VADへ渡す音だけ最大4倍まで補正する。RNNoise後の実音声とAI入力をこの補正で増幅しない。雑音除去の強さ・判定しきい値・先読みは維持する。
- Composerと最終出力の単純なclipは、大きな波形を平らに切り詰めていた。ピーク時に減衰し120msで戻す`PeakGuard`へ変更した。ゲインは区間をまたいで保持し、増幅・待ち時間・サンプル数変更を加えない。
- 入力の過大サンプル数と出力ピーク抑制量を計測に追加した。マイク側で既に割れた波形を修復する機能ではない。

SeedModelのASTと個別フィルタは元と一致する。Tinyの4/6/8ステップ、180/240/300ms、履歴、40msの再生余裕、4 CPUスレッド、CUDA Graphの計算は変更していない。今回のVADと出力保護は元アプリに対する意図的な変更であり、全処理が同一とは扱わない。既存のユーザーの声質・フィルタ・ゲイン設定を上書きしない。

## 公開音声と合成波形

検証素材は、元アプリの`build/jvs001-sample.wav`から最初の発話を含む6秒を使った。前後1秒の無音を付け、通常/0.65倍速、0/-18dBの4条件で発話判定を比較した。低速化は`librosa.effects.time_stretch`を使った人工的な条件で、本人の発声の再現ではない。

小音量・低速条件でマスクを掛けた後に残る元音声のエネルギーは98.667%から99.977%になった。雑音除去後のRMS比は変わっていない。これはマスクで消える音の減少を示す指標で、認識精度や文章の聞き取り率ではない。他の3条件は変更前後とも99.9999%前後だった。[変更前](gate-analysis-before.json)、[変更後](gate-analysis-after.json)、[検証スクリプト](analyse_gate_after.py)。変更前の別案`lessDenoise`は採用していない。

振幅2・180Hz・1秒の合成正弦波では、上限に張り付くサンプルが33,960から3,758へ減った。定常部分を音量調整した元波形と比べた形の相対誤差は約0.94%。抑制量は約7.02dB、追加バッファは0。最初のピーク付近には歪みが残り得るため、無歪みの保証ではない。[数値](peak-analysis.json)、[スクリプト](prepare_evidence.py)。

## 回帰確認

- Python49件成功。小さい声の判定用補正が実音声を変えないこと、ノイズのみの抑制、ピーク保護の増幅なし・通常音声の一致・区間をまたぐ連続性・無音での回復、ゲイン調整後の計測を含む。[ログ](python-tests-final.log)。
- デスクトップ2ファイル9件成功。調整後メーターと過大入力表示を含む。[ログ](desktop-tests.log)。変更したUIのlintと本番ビルド成功。[lint](lint.log)、[ビルド](build.log)。ビルドの既存の循環依存・chunkサイズ・import混在の警告は残る。
- バランス75秒: 低速0.65倍・-18dBの公開音声、入力ゲイン+6dB、厚み+3dB、柔らかさ+6dB。無音と発話を繰り返し、7回の声質/フィルタ変更を含む。不足・overflow・入力/出力異常0、Muteの最終PCMは全て0。[結果](live-balanced-slow-quiet.json)。
- 最速/安定優先は通常の公開音声で各30秒、各3回の設定変更。不足・overflow・入力/出力異常0。[最速](live-fast.json)、[安定優先](live-stable.json)。

実時間試験は公開PCMを実入力デバイスの時計で投入し、出力を常にMuteにした。マイク録音と外部送信は行っていない。公開音声から作った試験用WAVは`.cache`の一時ファイルだけで、製品やこの記録には含めない。GPU・音声mutexを使う試験は順に実行した。

## 配置済みアプリ

本番ビルドと音声ソースをインストール先へ配置した。[配置ログ](install.log)と[SHA256検証](installed-hashes.json)を保存した。実行ファイルと主要音声ファイル9点の一致、元アプリの記録済みソース不変、SeedModelのAST・個別フィルタの一致を確認した。

既存のアプリが動いていないことを確認して、本番GUIを検証用に起動した。バランス品質・入力+6dB・厚み+3dB・柔らかさ+6dB・実マイク・Muteの15秒で不足/overflow/解析落ち0、処理129ms、推定内部遅延974ms、pageerrorなし。入力/出力機器を各4件列挙し、調整後メーターと追加の計測項目を確認した。単体75秒試験の最終内部遅延は678msで、GUI測定との差がある。遅延の改善や常時同じ値を保証する結果とは扱わない。[GUI結果](voice-clarity-live.json)。

960×600で音声パネルの横方向のはみ出しなし、検証用アプリAPIなし。表示確認後、今回起動したアプリだけ終了した。制作プロジェクトを読み込み・保存していない。[画面](voice-clarity-live.png)。画面の声質スライダーは新規プロジェクトの値で、実行検証の一時設定をプロジェクトへ反映していない。

## 制約と次の確認

本人の小さい発話が言葉として改善したか、無音からの最初の一文字の不快な音量差がなくなったか、音程が変わる際の電子感が減ったかは未確認。今回のピーク保護は音割れを減らす処理で、音量の小さいピークまで自動で揃える機能ではない。音程や発音のAI生成自体を変更していないため、電子感の解消を保証しない。

OBS/ゲーム/顔追跡の同時負荷、長時間運転、本人の聴感はこの検証に含まない。更新後、既存のバランス品質・柔らかさ・厚みの設定で比較する。
