# I-079/I-078 パーツのワープと格子の向き・2026-10-12

画像パーツへ直接ワープを付けられるようにし、ワープのパレットのグループ作成を省いた。画像自身・親の格子を対象の候補で切り替えられる。新規格子は基準の変形で画面の横向きに合わせ、傾きのキーでは絵と一緒に回る。既存格子は［格子をまっすぐにする］で明示的に調整する。CC-021、保存形式8。

## 検証

- 全10パッケージ・312ファイル・2,692件。schema12/100、core68/692、desktop168/1,375。新規16件。全体実行の取り込み取消1件で、Worker生成前に取り消す競合を確認。起動後の停止を測るテストとして進捗を待ち、desktop全体を再実行して成功した。
- 全パッケージとe2eの型、lint、整形が成功。WebView2の全e2eは16ファイル・29件成功。
- Edge 1440×1000/800×600、WebView2 1440×1000/960×600（DPI125%）で、画像・グループへの追加、元の絵の不変、8°回転での格子の向き、実ドラッグ、15°の傾きキーへの追従を確認した。
- 密度のある曲げた格子で、向き調整前のずれ表示・取消・反映・Undoを確認。画面の測定は大きい窓1.39px、小さい窓3.81px。窓によって同じ18pxのドラッグがモデル空間で異なる量になるため、ずれも異なる。
- 画像自身にワープがある状態で、選択変形・メッシュ・輪郭線・ワープを実ドラッグ。+30を直した後0を直しても、+30のキーと全頂点は移動0px。基準の形を変えず、0のキーをロック。差を消す操作とUndoも成功。
- WebView2の各ツール・各サイズで、画像自身のワープと角度を実ファイルに保存・再読込し、全キーと0/+30の見た目が一致した。形式8のまま。pageerror無し。
- coreでは格子内外の恒等写像、自己・親ワープの適用順、制御点の二重適用防止、格子向きの変更・範囲の拡張・非ゼロ既定値キーの保持、曲面の生成を確認。schemaでは7→8で格子を変えず、角度の保持と不正値・旧読み込みでの拒否を確認。

## 制作モデルの測定と適用範囲

`projects/cardigan-bob-20261010/project.json`を読み取り、11格子を309姿勢で比較した。最大21.4288pxのずれがあるため、曲げた格子を「ほぼ同じ形でまっすぐにできる」とは扱わない。測定値は[model-audit.json](model-audit.json)。元ファイルのSHA256は不変。

既存格子を開いただけでは変更しない。調整時は既定値・全キーの座標・1軸の中間の姿勢で全描画頂点を測り、最大ずれを先に表示する。0.01pxを超えると確認してから反映し、取消では変更無し、1回でUndoできる。表示値は確認した姿勢の値で、未確認の全組み合わせの上限ではない。

基準の変形の横方向へ合わせる範囲。親の非一様な拡縮・非線形ワープとキーによる傾きは一緒に掛かる。常に画面正対する枠は作っていない。
