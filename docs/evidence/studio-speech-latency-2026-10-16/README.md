# 文字入力後の読み上げ待ち時間の短縮

2026-10-16。RTX 4050 Laptop 6GB、固定版Qwen3-TTS Base 1.7B、参照WAVと声質設定を維持して測定した。

## 変更

- 残差コード予測の15段をCUDA Graphで一括実行する。各段のlogitsは元のDynamicCache経路とビット一致を確認してから適用する。非対応・不一致・想定外の入力は元の処理へ戻す。モデル・精度・サンプリング設定は同じ。
- 文字Embeddingの593.5MiBを通常メモリへ移す。元の行をそのままGPUへコピーし、演算や量子化を追加しない。実GPUで参照結果の完全一致を確認した。合成の主モデル・話者・波形復号はGPUで実行する。
- 入力監視の待ち時間を450msから150msへ短縮する。IME待機、最新全文のみ、送信前は無音、送信時の一致確認は維持する。
- モデル解放ボタンをメイン画面の折りたたみの外へ出す。
- 出力開始の診断を追加する。無音でバッファをためるcallbackは数えず、最初の生成サンプルを実WASAPIへ渡すDAC時刻を記録する。
- 先頭の音声も後続と同じ640ms単位で渡す。従来の先頭320ms＋次640msは後処理後に約955msとなり、1秒しきい値ではさらに640ms分の合成を待っていた。640ms単位なら2チャンクで開始でき、開始・不足後の再開に1秒分をためる条件も維持できる。

## 同じ音声を生成する交互比較

「こんにちは。今日もよろしくね。」の2.56秒音声を、読込済みの同じモデル・同じ参照声・同じseedで元の処理→最適化→元の処理→最適化の順に生成した。両経路で文字EmbeddingのCPU配置と最終版の640msチャンクを共通にし、CUDA Graphの効果を比較している。CPU配置前のメモリ逼迫時の単発116秒という値は、この比較へ混ぜない。

| 指標 | 元のコード予測 | 最適化後 |
| --- | ---: | ---: |
| 合成時間の中央値 | 7.495秒 | 2.895秒 |
| 最初のPCMまでの中央値 | 1.986秒 | 0.847秒 |
| 音声の長さ | 2.56秒 | 2.56秒 |
| Float32 PCMのSHA256 | 全4回で一致 | 全4回で一致 |

合成時間は約61%減、約2.59倍の速度。最初のPCMは音声データの受信であり、出力開始とは区別する。モデルの初回読込と最初のCUDA Graph準備は別に必要。

[全測定値](comparison.json)。計測は通常のデスクトップ上で行い、他アプリの負荷を固定していない。各回の時間にはばらつきがあり、全ての文章・同時負荷で同じ速度を保証する値ではない。単語や文を分断して早く見せる方法は採っていない。

## 実アプリの検証

Python78件、関連デスクトップ44件、TypeScript本体／e2e、変更したTypeScriptのlint・整形、本番ビルドが成功した。実GPUのTauri結合5件が成功し、最後のチャンク調整後も固定話者・先行合成・入力直後の送信の2件を再検証した。

モデル読込済みで、音声の準備完了を待たずに入力直後にCtrl＋Enterで送信した。1秒分をためる条件を維持した実WASAPIの開始時刻から、入力操作開始→出力開始を算出した。全てMuteで、聴感を評価する試験ではない。

| 入力 | 入力開始→最初の音声のDAC時刻 | 再バッファ |
| --- | ---: | ---: |
| こんにちは。今日もよろしくね。 | 1.910秒 | 0回 |
| 明日は晴れるかな。楽しみだね。 | 1.803秒 | 0回 |

[出力開始の全データ](native-latency.json)、[先行合成・IME・話者固定](native-draft.json)、[入力ウィンドウ](fixed-speaker-draft.png)。出力開始は合成済みキャッシュの即再生だけを測った値ではない。Muteでも生成サンプルを消費した最初のcallbackだけを数え、無音のpriming callbackを除外した。

従来の[全文方式](regression-whole.json)、[逐次方式と別ウィンドウ](regression-stream.json)、途中停止も通過した。2文章の結果は長文や高負荷での無中断を保証しない。最終版も合成速度は実時間を少し超えるケースがあり、初回モデル読込、長文、他アプリとのGPU競合では待ち時間が残る。

ユーザー用Studioが閉じられていることを確認してから、通常の識別子でビルドした改善版を既存のインストール先へ反映した。[実行ファイルと音声処理7ファイルの配置hash](installed.json)は検証済みソースと一致する。本番JSに検証用`__studio`は含まれない。ユーザーの起動中アプリを終了する操作は行っていない。
