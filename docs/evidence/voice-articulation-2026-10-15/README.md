# 発音の崩れ・「ん」の音量増加の調査

2026-10-15 CO。統合後Studioで「舌足らずな発話」「んの時に音が大きくなる」という報告を受けた。実音声の聴感は未評価で、この2症状が解消したとはまだ扱わない。確定したRNNoiseの時間合わせの不具合を修正し、声質調整による相対的な低音の強調を測定した。

## 確定した不具合

同梱の`voice-noise.dll`は960サンプル（48kHzで20ms）遅れて出力する。取り込んだ元の`quality_voice/audio_processing.py`は480サンプル（10ms）と想定し、除去後の音声と異なる時刻の元音声を混合していた。これは元コードにもある不具合で、元アプリは変更せず統合版で修正する。

実DLLへ公開音声`liverVoiceChanger/build/jvs001-sample.wav`を入れ、出力と入力のずれ0〜1440サンプルの正規化相関を比較した。最大は960サンプルで0.993252、従来の480サンプルでは0.034042だった。同梱ソースの`denoise.c`にも、解析/合成の重複に加えて`delayed_X`を合成してから現在のスペクトルを保存する処理がある。DLLのSHA256は`assets.json`に固定している。[実測](alignment-before.json)、[再現スクリプト](analyse_alignment.py)。

入力クリーンアップは最初の2フレームを除き、20ms前の元PCMを保持して同じ入力時刻の音声だけを混ぜる。発話判定OFF・雑音除去ONの最低先読みを10→20msへ直す。発話判定ONの既定先読み128ms、AIの80ms先読み、Tinyの区間長・生成履歴・品質・40msの再生余裕は変更しない。雑音除去OFFなら遅延補償を加えない。出力PCMの長さ・DAC時刻・保存形式11は不変。

公開音声を731サンプルずつ投入し、強さ40/50/85/100%で実DLLの出力を960サンプル補正して作った参照混合と完全一致した。[修正後](processing-after.json)、[再現スクリプト](analyse_processing.py)。これは混合位置の検証で、音声認識率や聞き取り率の数値ではない。

従来の遅延テストは10ms遅延を模した仮実装を使っており、実DLLとの想定違いを見落としていた。今回、実DLLと位相が連続的に変わる合成倍音を使い、最大相関のフレーム位置と混合波形を検証する回帰テストを追加した。

## 「ん」の音量と声質調整

コード上、VAD用の最大4倍補正は判定用音声だけに適用される。実際のAI入力を増幅しない。前回追加したピーク保護も減衰のみで、自動的な音量増幅はしない。

厚み+3dB・柔らかさ+6dBと既定フィルタの測定では、200Hzの減衰は約0.50dB、6000Hzは約6.40dBだった。両者の相対差は約5.90dBになる。中立の声質と既定フィルタでは200Hzがほぼ0dB、6000Hzは約1.02dBだった。強い設定で高音に対して低音が目立つことを示すが、合成正弦波での測定であり、特定の「ん」の増加を再現した結果ではない。[帯域ごとの数値](processing-after.json)。

本人の音声がないため、AI生成・声質/フィルタ・入力機器・外部の通話音量補正のどれが「ん」を大きくしているかは確定していない。フィルタ全体OFFと元音声の試聴で同じ現象が出るかを確認中。声質・フィルタ・ゲインを勝手に書き換えず、音素別の圧縮やさらに強い高音除去は追加しない。フィルタ全体OFFでも声質3項目は有効なので、厚み0dB・柔らかさを下げた比較も有用。

## 検証

Python50件成功。実DLLの混合/遅延、発話保護、ノイズ抑制、ピーク保護、IPCなどを含む。[ログ](python-tests-final.log)。最初の追加テストは、合成倍音の相関値に根拠なく0.9以上を要求して失敗した。最終版では品質の点数にせず、960サンプルの相関が他の候補より高いことと、実出力との混合一致を検証する。[初回ログ](python-tests.log)。

バランス75秒の実時間試験は、0.65倍速/-18dBの公開音声、入力+6dB・厚み+3dB・柔らかさ+6dBで実施した。無音からの再開と7回の声質/フィルタ変更を含み、不足・overflow・入力/出力異常0、Muteの最終PCMは全て0。[結果](live-balanced.json)。GPU/音声mutexを使う試験は順に実施し、マイク録音や外部送信を行っていない。

音声Pythonだけの修正で、UI・Rust・モデルの再ビルドは不要。本番アプリへ音声ソースを再配置した。[配置ログ](install.log)、[SHA256検証](installed-hashes.json)。主要ファイルと実行ファイルの一致、元アプリの記録済みソース不変、SeedModelのASTと個別フィルタの一致を確認した。

配置済み本番アプリを検証用に起動し、バランス品質・実マイク・入力+6dB・厚み+3dB・柔らかさ+6dB・Muteで15秒実行した。不足/overflow/解析落ち0、処理98ms、内部遅延684ms、pageerrorなし。機器各4件、調整後メーター、960×600で音声パネルの横の収まりを確認した。今回起動したプロセスだけを終了し、制作プロジェクトを開いたり保存したりしていない。[GUI結果](voice-articulation-live.json)。

本人の発音、「ん」の相対音量、音程変化時の電子感、長時間と他アプリ併用の品質は未確認。これまでのMute試験の成功は、聞こえる音声の自然さの合格を意味しない。
