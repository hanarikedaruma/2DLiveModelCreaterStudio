# 全文／逐次の切替と別入力ウィンドウの検証

2026-10-15。基準モデルの写しと専用のアプリ識別子を使い、実CUDA GPU、Sound Blaster Play! 3のWASAPI出力で検証した。実出力はMute。マイクは未選択。制作中のプロジェクトと元のliverVoiceChangerは変更していない。

| 測定 | 全文生成後 | 逐次再生 |
| --- | ---: | ---: |
| 初回モデル読込 | 18.17秒 | 15.25秒 |
| 生成開始→最初のPCM | 全文完成時 | 2.71秒 |
| 全生成 | 13.14秒 | 15.17秒 |
| 生成音声 | 3.12秒 | 3.60秒 |
| 実出力解析フレーム | 312 | 1315（バッファ待機の無音を含む） |
| 途中停止 | 85.6ms | 537.3ms |
| 停止後のモデル | 解放 | 保持 |

文章と場面が異なるため、生成速度・音質の同条件比較ではない。最初のPCMは24kHzの生成結果であり、実際の最初の音ではない。逐次側は1秒分を蓄えて再生し、初回には上記のモデル読込も加わる。逐次のRTFは4.21、再バッファ2回。連続して実時間に合成できる性能基準は満たしていない。既定の全文方式を残し、ユーザーが逐次を選べる形にした。

## 確認した挙動

- Tauriの実機結合3件が成功。全文生成、逐次生成、生成途中の停止、モデル保持、最終PCMの有限値・時刻順序・Muteを確認。
- 入力ウィンドウは一つだけ開き、再度開くとフォーカスを移す。子側でメインの音声サービスを起動しない。
- 子から逐次方式へ切替・送信し、メインの状態と設定へ反映する。生成中も子で次の文章を書ける。
- 子を閉じてもメインが生成を継続する。開き直したあとに停止できる。全文方式へ戻し、プロジェクトを保存・再読込して方式を確認。入力した文章は保存されない。
- Python68件、関連デスクトップ40件、保存形式・出力ルーター12件が成功。PCMの短いread、破損ヘッダー、リサンプラーの区間分割不変性、リング上限、無音不足時の待機、ミュート、途中停止した発話の文脈除外、旧保存形式、古いプロジェクト・異なるtoken・重複要求も確認。
- デスクトップ本体とe2eのTypeScript検査、変更したTypeScriptのESLintを実施。通常版のビルドでは`VITE_E2E`を外す。

WindowsでSciPyの初回拡張読込がstdin監視スレッドと併用したときに停止する現象を、スタック出力付きの単独ワーカーで再現した。モデルを読み終えてから監視を始める順序へ変更し、通信と実アプリの再試験を完了した。初回読込中など協調停止できない間は、3秒後に所有するプロセスだけを終了する。

音声コードは完全な16群を扱い、最初4フレーム、以後8フレームで復号する。1フレーム1920サンプル／24kHz。復号の左文脈25フレームを保持する。固定モデル・依存版・対象ソースhashは`tools/voice-engine/speech-stream-source.json`に記録し、不一致では逐次方式をエラーにする。自動で全文方式へ切り替えて再発話しない。
