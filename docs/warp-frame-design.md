# ワープの格子の向きと、パーツへのワープ（設計）

2026-10-12 CL。ユーザーの要望（課題は I-078・I-079）。その後、操作性優先の実装指示を受け、下記の推奨D1〜D6を採用した。

## 採用仕様と実測（2026-10-12）

契約番号はCC-021、保存形式は8。画像のワープを自身の変形の前に掛け、点の変換・メッシュの逆算・制御点の表示をそろえる。画像へ直接追加でき、対象の候補にも子孫の画像を含める。新しい格子は基準の変形で画面の横向きに合わせる。親の非一様な拡縮・非線形ワープと、キーの傾きは一緒に掛かる。

既存の格子は開いただけでは作り直さない。［格子をまっすぐにする］で一次の写像を保持して再標本化し、曲げた格子の近似誤差を実測する。既定値・全キー座標・1軸の中間の姿勢で全描画頂点を比較し、確認した姿勢の最大ずれを上へ丸めて表示する。0.01px超なら適用前に確認。取消では変更無し、適用は1回のUndoで戻せる。

制作モデルのJSONを読み取りで確認したところ、11格子・309姿勢で最大21.43pxのずれがあった。設計時の「わずか」という見込みでは扱えないため、実測値を見てから適用する仕様にした。元のプロジェクトは変更していない。測った姿勢以外の全組み合わせでの上限は保証しない。[測定値](evidence/warp-frame-2026-10-12/model-audit.json)。

## 解決したいこと

ユーザーの言葉:

> パーツを回転させて斜めにしたときに、ワープの枠も斜めになってしまって操作しづらい。移動変形ツールでは斜め状態でいいのだが、ワープツール時は正面の四角であってほしい。

> ワープがグループに対してのみである必要性はあるか？ １パーツに対して、ワープをかけたいときに、１パーツグループを作って対応したので、もはやパーツでワープできてもいいような気がする。

これを、次の2つにまとめる。

1. 回転したグループ（またはその親）にワープを付けても、ワープのツールでは、格子が画面に対してまっすぐな四角に見えるようにする（I-078）。
2. 画像パーツにも、グループを作らずにワープを付けられるようにする（I-079）。

## 考え方

### 1. 格子の向き（I-078）

格子の四角の向きを、ワープごとに持たせる（`Warp.angle`。省略は 0 で今と同じ）。

- ワープを付けるとき、その時点のグループ自身と親の回転（基準状態の値）を打ち消す角度を入れる。すると、基準状態では格子が画面に対してまっすぐな四角になる。
- 格子の点の割合（u, v）は、四角を `angle` だけ回した向きで求める。制御点の動き（キーの差）も、その向きの格子の上で持つ。
- 顔の傾き（FaceAngleZ）など、パラメータで回る分は打ち消さない。頭を傾けると、格子も頭と一緒に傾く（ワープが頭と一緒に回るのが正しい動きのため）。基準状態（正面）では、まっすぐに見える。
- 親の回転と縦横の違う拡縮が重なると、格子は平行四辺形になる（今と同じ）。まれなので、今回は扱わない。

すでにあるワープ（`angle` が無いもの）は今のまま。パレットに［格子をまっすぐにする］を置き、押すと格子を今の回転に合わせて作り直す（D2）。

- 作り直しは、新しい格子の点の位置で、元のワープの動き（基準の形と、各キーの形）を読み取って新しい制御点にする（I-009 の［範囲を合わせ直す］と同じやり方）。
- 元の動きが格子の上で一次（平行移動・回転・拡縮・傾き）なら、ずれは出ない。曲げたワープでは、わずかに変わる（試算で確かめ、ずれの最大をパレットで知らせる）。1回の Undo で戻せる。

```
今（グループを 8° 回した顔）           これから（基準状態）
    ╱‾‾‾╱‾‾‾╱                          ┌───┬───┐
   ╱   ╱   ╱   ← 格子が斜め             │   │   │  ← 画面にまっすぐ
  ╱‾‾‾╱‾‾‾╱                             ├───┼───┤
 ╱___╱___╱                              │   │   │
                                        └───┴───┘
```

ほかの案と比べたもの:

| 案                                    | 中身                                                                     | 良い点                                   | 悪い点                                                                                    |
| ------------------------------------- | ------------------------------------------------------------------------ | ---------------------------------------- | ----------------------------------------------------------------------------------------- |
| A（推奨）: 格子の向きを持たせる       | 上に書いたとおり                                                         | 頭を傾けたときも、ワープが頭についてくる | 保存の形が変わる（schemaVersion 8）。既存のワープの作り直しは、曲げたものでわずかにずれる |
| B: ワープをグループの回転の後に掛ける | 格子を親の座標に置く                                                     | 格子はいつもまっすぐ                     | 頭を傾けるキーで、顔の向きのワープが画面の横のまま掛かり、形が崩れる                      |
| C: 見た目だけまっすぐな四角を描く     | 本物の制御点は斜めのまま、まっすぐな四角の点を動かすと近い制御点を動かす | 保存の形も計算も変えない                 | 描いた点と本物の制御点が重ならず、思った所が動かない                                      |

### 2. 画像パーツのワープ（I-079）

画像パーツにもワープを付けられるようにする（D3）。

- 計算の順番: 頂点の差 → **そのパーツ自身のワープ** → パーツ自身の変形 → 親ごとに「ワープ → 変形」。グループのワープと同じく、自分の変形の前に掛ける。格子はそのパーツの絵（メッシュ）を囲む四角で、向きは 1. の `angle` で、付けたときに画面にまっすぐにする。
- メッシュの頂点のキーは、ワープの前の位置で持つ（今のグループの中のパーツと同じ）。メッシュ編集・輪郭線・流れ線・揺れ（物理）など、メッシュの点を画面の位置にする所（`space.ts` の `lift` を使う約10か所）に、自分のワープを足す。
- ワープのツールで画像パーツを押したときの対象（D4）: そのパーツにワープがあればそのパーツ。無ければ、ワープの付いたいちばん近い親のグループ。どれにも無ければ、押したパーツ。パレットの［対象を変える］で、押したパーツと親のグループの中から選び直せる。
- ［グループを作る］はパレットから外す（D5）。
- 1つのパーツに付けるワープは1つ（今のグループと同じ）。

### 保存の形と契約（CC-017）

- `Warp.angle?: number`（ラジアン。省略は 0）。`Warp.partId` の説明を「ワープを付けたパーツ（グループか画像）」に直す。
- schemaVersion を 7 → 8 にする（D6）。8 の前のアプリで、画像パーツのワープや `angle` を黙って無視して違う形で描くのを防ぐため。7 → 8 の移行は何もしない（足すだけ）。
- `docs/contract-changes.md` に CC-017 として書く。

## テストと確認

- 単体（計算）: `angle` 0 のワープは今と同じ形（今のテストがそのまま通る）。`angle` のある格子で、制御点を動かさなければ形が変わらない。回したグループに付けたワープの格子が、基準状態で画面にまっすぐ。頭を傾けるキーで、格子が頭と一緒に回る。
- 単体（作り直し）: 一次の動きのキーは、作り直してもずれない。曲げたキーのずれが、知らせる値の中に収まる。1回の Undo で戻る。
- 単体（画像パーツのワープ）: 画像パーツのワープで絵が変わる。メッシュの頂点のキー・輪郭線・流れ線・胸揺れを重ねても、ドラッグした点がマウスの下に来る。グループのワープと重ねると、内側（画像）→ 外側（グループ）の順に掛かる。
- 直す既存のテスト: `pipeline.warp.test.ts`・`space.test.ts`（画像パーツのワープを使わない、を逆にする）、`warp.test.tsx`・`warpPalette.test.tsx`・`warp.c60.test.tsx`（グループだけを選ぶ所）、`warpOps.test.ts`。
- 画面: 開発サーバーで 1440×1000・800×600。顔のグループを 8° 回してからワープを付け、格子がまっすぐなこと、制御点のドラッグが思った向きに動くこと、髪1枚にワープを付けて曲げられることを画像に残す。
- ユーザーのモデル（`projects/cardigan-bob-20261010`、頭のグループを 8° 回してワープ 11 個）を写して、［格子をまっすぐにする］の前と後の形の差を測る（元のファイルは触らない）。

## 完成の条件

- 回したグループ・画像パーツに付けたワープの格子が、ワープのツールでは画面にまっすぐな四角に見える（基準状態）。
- 頭を傾けるなど、パラメータで回したときは、ワープが頭についてくる。
- 画像パーツを選んでワープを付けられ、1パーツのグループを作らなくてよい。
- 今あるワープの形は、［格子をまっすぐにする］を押さない限り変わらない。
