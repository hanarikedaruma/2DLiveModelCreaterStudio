## 先に結論

**いまあるのは、平面画像を曲面らしく変形する仕組みであり、側面・裏側の絵を備えた円筒や球体を回す仕組みではない。**

- 額や頬が素材には描かれていて、別パーツの髪に隠れているだけなら、髪との位置関係が変わることで見せられる。
- 素材に描かれていない横顔・髪の裏側は、座標を動かすだけでは新しく現れない。
- 回転に応じて「耳が顔の後ろから出る」「遠い側の部品が隠れる」といった処理も、変形とは別に必要になる。
- 頭部を共通の親とし、顔と髪は別グループにする。ただし、それだけでは素材不足や隠れ方は解決しない。

## 追加する要件

1. 頭部の向きは共通の基準から求め、顔・髪・耳がその向きに整合して動く。同じ回転に相当する変形を二重に掛けない。
2. 新たに見える場所を「素材があり隠れていた領域」「側面等の補助素材で補う領域」「素材がない領域」に分けて扱う。
3. 見える面・隠れる面・部品間の前後関係を、頂点の移動とは別の責務として設計する。
4. 顔と髪は別グループのままとし、パーツごと・向きごとの手動修正、キーのロック、髪の物理揺れを維持する。
5. 設定した頭の向きの範囲内で、必要な素材とメッシュが足りるか確認できる。素材不足を勝手な引き伸ばしや生成画像で埋めない。
6. 旧モデルは明示的に変換するまで旧方式で表示し、既存の見た目・描画順・手動キーを勝手に変えない。

## 頭部のグループ構成

既存のheadRootを頭部の親として再利用し、髪をまとめるhairGroupを追加する案を基本とする。下の名前は設計上の識別名であり、まだSchemaには追加しない。

```text
headRoot（頭部の共通基準）
  faceGroup（顔の局所変形）
    顔の輪郭・肌
    目・眉・口・頬
    必要に応じた顔の側面素材
  hairGroup（髪の共通調整）
    前髪
    左右の横髪
    後ろ髪
    必要に応じた側面・裏側素材
  左右の耳
  頭に付くアクセサリ
```

- headRoot: 共通の中心・寸法・向きの基準を持つ。既存の傾き（FaceAngleZ）の頭と首の分担も移行時に確認する。
- faceGroup: 共通の頭の動きに対する顔の形の補正、表情、目・口などを担当する。
- hairGroup: 共通の頭の動きに対する髪全体の補正を担当する。その下の髪パーツは、個別の付け根・奥行き・手動変形・物理揺れを持つ。
- 耳・アクセサリ: 頭部共通の動きへ追従しつつ、個別の奥行きと隠れ方を持つ。顔や髪に付けたほうが適切な素材は明示的に所属を変えられる。
- **親子構造と描画順は別。** 同じhairGroup内でも、後ろ髪は顔の後ろ、前髪は顔の前へ描ける。hairGroupを1枚へ合成して全体を一括で前後に置かない。
- 新グループを挟むだけではFaceAngleX/Yの問題は解決しない。既存の奥行き移動・顔ワープとの重複を整理した共通の姿勢計算が必要。

## 隠れていた部分の扱い

| 場合                                 | 表示方法                                                       | 自動設定と利用者の分担                                                     |
| ------------------------------------ | -------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 額・頬が髪の下まで描かれている       | 元の素材を変形し、髪が移動して露出した画素を表示する           | 素材を切り詰めず必要領域までメッシュ化する。利用者が覆われ方を調整できる   |
| 側面・耳の付け根などの補助素材がある | 頭部と同じ向きで動かし、指定した角度範囲・マスク・順序で見せる | 利用者が素材の役割と有効範囲を指定し、自動設定はその指定から初期キーを作る |
| 必要な側面・裏側が描かれていない     | 完成した立体のように表示できるとは扱わない                     | 描き足しまたは別素材を案内する。現素材で確認済みの回転範囲を設定可能にする |
| 別のパーツが手前に来て隠れる         | 回転に応じた可視範囲・マスク・描画順で隠す                     | 単にパーツ全体を消すのではなく、部分的に隠れる領域も検証する               |

初版はPSD/PNGの描き足し・補助素材を使う方針を提案する。画像の自動生成や左右反転による穴埋めは既定動作に含めない。非対称の髪型・模様を反転コピーで壊さない。

素材の画素が存在しても、メッシュがその部分を覆っていなければ表示できない。PSD再読み込みでのメッシュ範囲不足（I-034）も受け入れ確認に含める。絵柄による意図的な透明部分と素材不足を画素だけで完全に判別できるとは仮定せず、必要領域の指定とプレビューによる確認を併用する。

## 回転・表示の処理方針

1. FaceAngleX/Y/Zから頭部の共通姿勢を求める。パラメータ値と実際に投影する角度は別として明示する。現行の値30が曲面の20度に対応する設計を、30度の立体回転と取り違えない。
2. 顔・髪・耳の形と奥行き、付け根、局所的な表情・揺れを共通座標系にそろえる。表情と揺れの適用順は調査方針の切り分けで確定する。
3. 共通の姿勢・投影から部品の画面上の位置を求める。必要な側面素材も同じ姿勢を参照する。従来のdepth移動をそのまま重ねて二重変形させない。
4. その姿勢で見せる領域を求め、対応する素材・メッシュ・UVが存在するか検証する。既存素材のUVを動かすだけで未知の側面の絵が得られるとは扱わない。
5. 向きに応じた隠れ方と描画順を適用する。固定順で成立するモデルは固定順を使い、変化が必要なものだけ明示的なルールを持つ。
6. 利用者の向きごとの補正を定義済みの座標系で合成して出力する。補正を投影の前後どちらに記録するかを曖昧にせず、再生成・Undoで同じ意味を保つ。

「共通の姿勢」と「全画像への同じワープ」は同義ではない。球面・楕円体等の共通投影から部品ごとに形を計算する方式も、親に変形を持たせて局所補正する方式も比較対象とする。

### 隠れ方の実装候補と制約

- 立体近似を使う場合、法線・奥行き等から可視面を判定し、裏向きに回った面が反転して透けて見えないようにする。ただし髪は両面が必要な場合もあり、片面/両面と裏側素材を部品ごとに定義する。
- 2D素材を使う初版では、向きごとのマスク・補助素材の表示範囲・描画順の指定を中心にする案を比較する。パーツ内で前後が交差する場合は、パーツ分割や部分マスクが必要で、パーツ単位の並べ替えだけでは解決しない。
- 切替角度の前後でちらつき、二重の輪郭、透明な隙間が出ないことを検証する。正しい遮蔽が必要な箇所を安易な半透明クロスフェードだけで代用しない。
- 手で非表示にしたパーツを、角度ルールだけで勝手に再表示しない。手動非表示、角度による可視性、通常の不透明度の合成規則を分けて定義する。

## 手動編集の保証

- 頭部の向きに対する前髪・横髪・後ろ髪の位置と形を、引き続き個別に編集できる。
- 髪の付け根の追従と毛先の揺れを分けて調整できる。髪を頭と同じ形に固定して編集不能にしない。
- 補助素材の割り当て、使う角度範囲、可視範囲、描画順を編集・プレビューできる。
- 自動生成された部分と手動で補正した部分を区別し、ロック・Undo/Redo・保存/再読込に対応する。
- 既存キーを新方式に正しく変換できない場合は、旧方式を保持したまま理由を通知する。推測でキーを消す・意味を読み替えることはしない。

## 検証と完了条件

1. 額まで描かれた顔が前髪で隠れているモデルで、回転時に既存の絵が自然に現れ、背景が透けない。
2. 側面素材があるモデルで、左右・上下・斜めに応じて必要な領域が現れ、遠い側は正しく隠れる。
3. 側面素材がないモデルで、未知の絵を自動生成・過剰に引き伸ばすのではなく、素材不足と未確認範囲を識別できる。
4. 同じ髪グループに属する前髪と後ろ髪が、顔の前後に別々に描ける。グループ追加で従来の描画順を変えない。
5. 頭の向きと物理揺れを同時に使っても付け根が離れず、手動で直した髪の形・キーのロックが維持される。
6. X/Yの49姿勢、連続往復、Z回転、左右非対称モデルで、形状・表示切替・マスク・UVの破綻がない。
7. 基準姿勢、旧モデル、新規モデル、明示的変換、Undo/Redo、保存/再読込で意図しない差分がない。
8. 同じ基準PC・モデルで現行版との性能比較を行い、最終段階でOBS出力も確認する。

調査の順序は、**素材とメッシュが足りるか → 共通姿勢と変形の重複 → 回転時の露出・遮蔽 → 手動編集と物理 → 移行・性能**とする。

全周360度の回転や、正面1枚から見えない裏側を完全再現することは現段階の達成条件に含めない。まず現在のFaceAngleX/Yの範囲を、用意された素材で破綻なく表現する。範囲を拡張する場合は、その分の形状・素材・隠れ方を追加設計する。
