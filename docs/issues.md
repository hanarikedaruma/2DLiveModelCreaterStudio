## I-001 カメラによっては 1280×720 で映像が遅い

- 現象: eMeet C980 Pro でトラッキングが 12.9fps（目標 30fps 以上）。動きがカクつく。
- 原因: カメラが 1280×720 のとき毎秒13枚しか映像を出さない（設定上は 30fps を返す）。640×480 と 1920×1080 では 25fps、内蔵の HD Webcam は 1280×720 で 29.5fps。推定を止めてカメラの映像だけを数えても同じなので、アプリ側ではない。詳しくは docs/studio-check.md の「2026-10-03 の計測」。
- 対応案: トラッキングの設定に解像度の選択（640×480 / 1280×720 / 1920×1080）を足す。または 1280×720 で始めて、届く映像が遅ければほかの解像度を試す。
- 判断が要る点: 設計書（カード15）は「1280×720・30fps を優先」と決めている。変えるなら設計書からの変更として docs/status.md に残す。

## I-069 ツールで操作中に、近くの別のパーツを押すとそちらに切り替わる

- **現象**（ユーザーの要望、2026-10-11）:「変形やワープなど何かツールを使用しているとき、ほかの要素の範囲を選択すると、そちらの編集状態になります」「変形時の、回転中心の◎をドラッグしようとすると背景のパーツにフォーカスされてしまって、操作できない」「何かを操作中、ほか要素に勝手に切り替わるのをやめたい。右クリックで解除してからか、要素の操作範囲からある程度外側のものを選択した時に切り替えが起きるようにしたい」「変形ツールで移動を行いたいときに、線を掴めず後ろ側のパーツを掴んでしまうなどの操作ストレスを軽減したい」
- **原因**（`apps/desktop/src/modes/modeling/canvas/selectTool.ts` の `onPointerDown`）:
  - 押した所を、ハンドル → その点の手前のパーツ → 選んでいる枠の中、の順に調べる。枠の中でも、その点に別のパーツ（後ろの背景・手前の髪など）があれば、そのパーツに切り替わる（I-050 で、最初の操作は選ぶだけにした）。枠の中の移動は、その点に何のパーツも無いときだけ。
  - ◎ をつかめる範囲は画面の 7px（回転・拡縮のハンドルは 11px。I-049）。パラメータの編集中・複数選択・プレビュー中・枠が小さいときは ◎ をつかめず、押すと次の判定へ進むので、◎ の下に別のパーツがあるとそちらに切り替わる。
  - メッシュ編集・ワープ・輪郭線のツールは、対象（メッシュ・グループ）のすぐ外で別のパーツを押すと、そのパーツへ切り替える（[パレットの設計](modeling-palette-design.md)の D1 で決めた動き）。

- **対応（2026-10-11 CL）**: ユーザーが設計の D1〜D8 をすべて推奨のとおり承認（「すべて推奨でよいです。実装はすべてCLが行います」）。同日に実装した。
  - 選択・変形: 操作範囲（枠・回転のハンドル・◎）と余白（画面の 24px）の中を押すと、手前や後ろに別のパーツがあっても切り替えず、選んでいるものを動かす。◎ をつかめる範囲を 11px に広げた。動かせない ◎ を押すと移動になり、◎ の下のパーツには切り替えない。Ctrl+クリックで押した所のパーツへ切り替える（何も無ければ外す）。Shift・I-050 の動きは今のまま。
  - メッシュ編集・ワープ・輪郭線: 対象（メッシュ・格子）と余白の中を押しても切り替えない。余白より外は今のまま切り替える。
  - マウスの形（`CanvasTool.cursorAt`、契約の変更 CC-016）と、余白より外で押すと切り替わる先の点線と名前（`canvas/targetRange.ts`）。
  - 確認: 単体（全体 2,616件、うち新規 15件）・型・lint・整形。開発サーバーの画面（1440×1000）で、モデルの顔を選び、前髪の上（枠の中）でマウスの形が移動になりドラッグで顔が動くこと（前髪は動かず選択も顔のまま、Undo の名前は「パーツの移動」）、◎ の横がつかむ形、枠の外が既定の形で、首を点線と名前で予告すること、Ctrl+クリックで前髪に切り替わることを確かめた。画像は `docs/evidence/canvas-target-lock-2026-10-11/`。本番アプリの更新は未実施。
