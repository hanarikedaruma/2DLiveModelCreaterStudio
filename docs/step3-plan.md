## 1. 結論

**STEP3 は改善だけを行う。** 改善とは、今ある機能の不具合・使いにくさ・欠けを直すことと、実機で確かめていない部分を確かめること。新しい機能・新しい編集の方法・新しい入出力は STEP4 の候補にし、STEP3 の後に検討し直す。

別のAIの結論（①トラッキングと自動の分離、②制作効率の優先、③配信を後回しにしない、④一括実装）は、コードで確かめて裏付けがあった。改善だけに絞ったうえで、次のように扱う。

## 5. 進め方（一括実装）

- **承認は最初の1回にする。** 本書の範囲・完成条件と6章の判断。以後は機能ごとに承認を求めない。
- **依存の順に進める。** カードの依存は実装計画の表のとおり。CL と CO は、触るファイルが重ならないカードを並行して進める。
- **確かめるのは、STEP2 までに作った仕組み。** 単体テスト・e2e・計測・見本のモデル・ユースケーステスト・実機の手順。新しい開発環境・スクリプト・リモートは作らない。
- **同じ作業フォルダで進める。** CL と CO は同じ作業フォルダの main で作業し、自分のカードのファイルだけをコミットする。約束は実装計画の「同じ作業フォルダで2人が進めるときの約束」。
- **途中の自動テスト。** 直す前に失敗するテストを先に書く。契約の変更は CC を記録する。直した課題の確認をユースケーステストに CH・UC-CH として足す。
- **最後の統合確認。** カード72（全体のテスト・e2e・実機・計測）。実機で確かめていないものは「完了」と呼ばない（[status.md](status.md) の約束のとおり）。
- **承認を求め直すのは次のときだけ。** 契約で決めた形を変える必要が出たとき、6章の判断の前提が崩れたとき、保存の形を変えて前の版のプロジェクトを変換するとき、改善のつもりの作業が新しい機能になると分かったとき（STEP4 の候補に回す）。

## 8. 根拠（コードの調査、2026-10-07）

値の合成

- ミキサーは1つ（packages/core/src/mix/mixer.ts）。層の順は tracking → bodyFollow → expression → animation → lipSync → periodic → physics（packages/contracts/src/index.ts）。実行部は層ごとに混ぜ直して次の層へ渡すが、層ごとの値は捨て、最後の params だけを残す（apps/desktop/src/modes/studio/runtime.ts）。
- 自動まばたきは、トラッキングの層の tick の中で、目のトラッキングがオフか顔が外れたときだけ EyeOpenL/R に入る（packages/tracking/src/mapping/producer.ts）。カメラを止めているときは、実行部が別に自動まばたきの層を作る（runtime.ts の trackingProducer）。
- 体の追従は別の層だが、トラッキングが書いた FaceAngleX/Z から計算する（packages/core/src/layers/bodyFollow.ts）。ホットキーのパラメータの上書きは、表情と同じ id の層で、順番は登録の順（apps/desktop/src/hotkeys/actions.ts）。
- 自動の視線・待機の動きは無い。顔が外れたときの「止める」（hold）は実装にあるが、アプリからは選べない。
- MediaPipe はブレンドシェイプを出すが、変換で10項目に減らし、口と眉は左右を平均する（packages/tracking/src/source/convert.ts）。頬のふくらみ・目の見開き・舌などは捨てている。

制作

- キーのコピー・貼り付けは無い。キーを1つ消す・動かす操作も無い（消せるのは格子のマスの補正のキーだけ）。
- 左右反転コピー（apps/desktop/src/modes/modeling/structure/mirrorCopy.ts）は、新しいパーツを作るだけで、元と連動しない。PSD に左右両方がある普通の場合には使えない。ワープと物理は写さない。
- 選んだ複数のパーツは、それぞれの回転中心で回る。メッシュとワープの点は矩形で選べるが、動かすだけ。
- 「間を生成」「すべて再補間」は、そのパラメータを使う全部のバインディングに掛かる（apps/desktop/src/modes/modeling/parameters/generate.ts）。
- タイムラインの補間は linear・smooth・step で、キーは1つずつしか選べない。

保存・共有

- プロジェクトはフォルダ（project.json・assets/・backups/）。schemaVersion 3 で、古い版は開くときに変換し、元を backups/ に残す。新しい版は拒む（packages/schema/src/migrate.ts）。
- 自動保存は 5 秒後、10 世代。強制終了からの復元がある。
- 素材の PNG が1つ欠けると全体を開かない（packages/io/src/project/projectIO.ts の readAssets）。書き込みは .tmp から名前を変えるが、失敗したときは移動先を消してから変え直す（apps/desktop/src/platform/tauriFs.ts）。
- 1つのファイルへの書き出し、ほかの形式への書き出しは無い。

出力

- 出力ウィンドウは透過できない（透過の背景は黒）。OBS ではウィンドウキャプチャとクロマキーで抜く（確認済み）。
- Spout2 は自前の送り手（Rust・D3D11）で、アルファ付きで送る。OBS での受信は未確認。描画のエラーは1回出力するだけで、デバイスを作り直さない（I-031）。既定の GPU だけを使う（I-032）。
- 仮想カメラ・NDI・録画は無い（仮想カメラは設計書で「作らないもの」）。

性能

- Web Worker は使っていない。PSD の解析（ag-psd）と顔の推定（MediaPipe）は、画面と同じ処理の流れで同期に動く（I-004・I-005）。素材ごとに PNG・ImageBitmap・ImageData を持ち続ける（I-003）。

確認の仕組み

- 自動テストは 218 ファイル・2,028 件（記録の最新）、本物のアプリでの e2e が 10 件、計測（`pnpm measure`）。ユースケーステストは 61 ユースケース・489 確認点で、実画面で OK になったのは 39 件。
