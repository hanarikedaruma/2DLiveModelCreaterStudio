## 実装で決めたこと（設計との違い）

- **設定の並び**：設計の図では項目名を左に置いたが、800×600 で「スタジオの設定」の幅が149pxしかなく、10pxはみ出した。項目名を上の行に置き、左腕・右腕の2列を下に並べた（どの幅でもはみ出さない）。
- **カメラの開始**：校正を始めるとき、顔の校正と同じ道（`studioRuntime.startTracking`）でカメラを開始するのは、実行部が止まっていて、かつサービスの体の認識も `off` のときだけにした（仮サービスでは本物のカメラを開かない）。
- **購読**：診断（毎フレーム）は、校正のダイアログと詳細を開いている間だけ購読する。状態はサービスの通知のときだけ読み直す（`status()` は呼ぶたびに新しいオブジェクトを返すため）。
- **スライダー**：動かしている間は画面の値だけ変え、離したとき（キーなら離したとき・外れたとき）にサービスへ渡す。保存（AT-12）で取り消しの記録が細かく積まれないようにするため。
- **点の判定**：Poseの visibility 0.5以上で枠の中を「見えている」とする（AT-05と同じ）。
- **ファイル名**：位置の計算を `skeleton.ts` にすると、Windows では `Skeleton.tsx` と大文字小文字だけの違いになり型検査が通らないので `points.ts` にした。

## COへの依頼（契約の追加）

設計の判断7のAのとおり、`ArmService` に次の3つを足すよう依頼する（[AT-03 CLレビュー](AT-03-cl-review.md#追加の依頼at-11から契約の追加)にも書いた）。画面側は [service.ts](../../../apps/desktop/src/modes/studio/arms/service.ts) に同じ形を置いてあり、契約に入ったら型を置き換えるだけにする。

| 足すもの       | 形（画面が使っている形）                                                                                                                                                                                                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 設定の読み出し | `settings(): ArmTrackingSettings`                                                                                                                                                                                                                                                                   |
| 校正の取り消し | `cancelCalibration(): void`。途中の手順の記録を捨て、前の校正を残す。数え中・集め中のキャンセルで、最後の手順が保存されないこと                                                                                                                                                                     |
| 診断と購読     | `diagnostics(): ArmDiagnostics \| null`・`onDiagnostics(listener): () => void`。`ArmDiagnostics` は撮影時刻、画像の大きさ、演者の左右ごとのPoseの肩・肘・手首（未反転の0..1と visibility。人がいなければ null）、手の手首、モデルの左右ごとの採用した肘・手首と有効性・目標と実際の手首・制限の理由 |

`FakeArmService` は設定を private の `settings` に持っているので、`settings()` を足すときは名前を変える必要がある（AT-11の試験では継承せずに包んだ）。

## AT-12へ渡す接続口

| 接続口                              | 内容                                                                                                                                                      |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `register()`（`modes/studio/arms`） | 本物のサービスを `services.arms` に入れた後に呼ぶ。開発用の入口は `services.arms` が既にあれば仮サービスを入れない                                        |
| `services.arms`                     | 上の3つを持つ `ArmService`。`setSettings` は Project の `armTracking` へ、校正の完了・`clearCalibration` は Environment の `armCalibration` へ保存する    |
| 状態・診断の意味                    | `status.tracking.pose.state === 'off'` はカメラが止まっている。`motion[side]` の状態・手の状態・手形・理由を左右の行と「手形を試す」で使う                |
| 準備の項目が読むもの                | `status.available`・`reason`、Pose・手の状態、`rigIssues`（モデルの `armRigs` も読む）、`calibration()`、今のカメラ（`captureStats` と `cameraDeviceId`） |
| ミラー                              | 画面は Environment の `mirror` で「どちらの手で動くか」と骨格の向きを決める。サービスの左右の割当（AT-05）と同じ規則                                      |
| 腕の校正のホットキー                | 足していない。要るならAT-12で、顔の「キャリブレーションをやり直す」とは別の名前で足す                                                                     |

## 未確認・制約

- 本物のサービス（AT-12）ではまだ動かしていない。実カメラでの位置合わせ・校正の失敗の出方は、AT-12の後に確かめる。
- Tauri のアプリ（live2d-studio.exe）では確認していない（ブラウザの開発サーバーだけ）。
- 仮サービスの診断の点は作った値で、実際の推定の揺れは無い。
- 800×600 ではスライダーが短い（1本 35px 程度）。操作はできるが、細かい値は詳細側に数値の欄を足すかをCOの確認で判断してほしい。
