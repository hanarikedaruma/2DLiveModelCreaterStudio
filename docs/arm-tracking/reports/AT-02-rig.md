## AT-03へ渡す契約候補

正式な保存型の決定はAT-01とCLの独立確認後に行う。以下はAT-02の入力であり、製品APIを先に追加したものではない。

### 座標と角度

- 単位はモデル空間のpx・度。x右向き、y下向き。モデル自身の左Lは画面右、右Rは画面左。カメラのミラー処理はこの層へ持ち込まない。
- 肩角sの0°は下向き。正角は体の外側へ上げる向き。肘eの0°は伸展で、eは常に0以上。手首wは前腕に対する相対角。L/Rとも同じ正規化角度を使う。
- 肩はL=(78,240)、R=(-78,240)、上腕長118、前腕長108。Lの各骨方向は `(sin(angle), cos(angle))`、Rはx成分だけ符号を変える。画像を負倍率で反転する操作ではない。
- 手形の共通原点は手首(0,0)、指の基準方向は(0,-1)。Lの手形回転は `180-s-e-w`、Rはその符号反転。角度の360°正規化・累積加算はしない。
- 休止角は(8,12,0)。素材の基準角と休止角は別に保存する。曲がった素材を想定した基準角(25,65,10)からの差分変換も照合した。

### 試した制限と優先順位

| 制限             | 範囲      |
| ---------------- | --------- |
| 肩 s             | -25〜160° |
| 肘 e             | 0〜145°   |
| 手首 w           | -40〜40°  |
| 前腕の合成角 s+e | -25〜300° |
| 手の合成角 s+e+w | -55〜300° |

これらは試作値であり、実素材に合う可動域はAT-15で狭めて調整する。合成角の区間幅も360°未満とし、1回転を許さない。瞬間的な大きい入力差の速度制限・ロスト復帰はAT-09が必要で、静的制約だけで自然さ全体を保証しない。

要求角の制約は「非有限入力なら休止 → 肩 → 肘と前腕の範囲 → 手首と手の合成角」の順。例えば(160,145,40)は(160,140,0)になり、(-25,0,-40)は(-25,0,-30)になる。

手首ドラッグ用の試作IKは、同じ肘の枝で2°の全域探索後に0.2°・0.02°で局所探索する。固定骨長・可動域を優先して目標誤差を残す。前回姿勢がある場合は角度変化に弱い罰則を加える。これはAT-06の製品IKの方式・最適解・実行速度を確定するものではない。

| Lの目標(px)        | 制約後の肩・肘 | 残る距離(px) | 解釈                                                           |
| ------------------ | -------------- | ------------ | -------------------------------------------------------------- |
| (1000,-1000)       | (143.36,0)     | 1319.2133    | 骨長を超えて伸ばさない                                         |
| (-1000,1000)       | (-25,0)        | 1128.4954    | 肩の下限を超えて回さない                                       |
| (78,240)           | (-24.6,145)    | 68.6255      | 肘を145°より深く折らない。肩上の目標では肩角が不定になりやすい |
| (95.3530,145.6416) | (110,130)      | 0            | 顔の前の姿勢は到達可能                                         |

AT-06では目標が肩に一致する場合の前回姿勢の保持と、制約の境目での連続性を明示的に検証する。試作でたまたま選ばれた肩角を正解として固定しない。

### 所有グループ・基準角・親への取付け

各側に専用の `upperGroup → lowerGroup → handGroup` を作り、肩・肘・手首をそれぞれ基準姿勢のpivotとする候補。上腕画像はupper、前腕画像はlower、4枚の手形はhandが所有する。同じ画像を複数リグで所有しない。左右のグループID・画像ID、骨長、基準pivot・基準角、休止角、角度制限、4手形の対応をリグ設定へ保存する。

既存の [space.ts](../../../packages/core/src/deform/space.ts) と [pipeline.ts](../../../packages/core/src/deform/pipeline.ts) は子から親へ変換する。試作の `referencePoint` も、手首差分→肘差分→肩差分→親変換を各1回適用する。各差分はLでは `-(現在角-基準角)`、Rでは `+(現在角-基準角)`。動いた世界座標へさらに親回転を重ねることを避ける。基準頂点はモデル座標に置き、単なる親からの相対座標と混同しない。

親は正の等倍率・回転・平行移動の対象とし、呼吸の上下移動は親に1回付ける。試作の親pivotは(0,260)。親回転23°・倍率1.7・呼吸6pxでも、接続と差分回転が一致する。既存の非等方拡縮・反転・非線形ワープを許す範囲はAT-03で明文化する必要があり、本試作では非対応。

旧ArmL/Rの全体回転や既存の手動キーフレームと、新しい関節差分の所有はAT-08で整理する。トラッキングだけでなく、他入力との合成後にも最終制約を適用する。

### 手形の接続・前後関係・重ね代

4手形は全て同じ手首原点と掌の大きさで、常に1種類だけ表示する。L/Rは指の長さと親指の輪郭を別データで記述した。掌の線・L/Rの文字・親指の紫点で、回転中も同じ掌面と左右を見分けられる。遷移の見本では進行50%で手形を切り替え、形状番号を補間しない。認識の確定待ちはAT-07、製品での表示選択はAT-08が担当する。

固定描画順は、胴体→上腕L/R→首・顔・前髪→前腕L/R→手L/R。現在の試作では重なった左右の手はRが前。必要な画像IDを製品のdrawOrderへ明示し、グループ階層と描画順を分ける。手が顔を隠しても押し戻さない。

上腕は幅35px・丸い端17.5px、前腕は外周幅27px、手首の掌幅26px・原点から袖側へ3pxの重ねを持つ。技術見本の16姿勢で接続の隙間がないことをCOが画像確認した。この形状だけでは袖の模様・陰影・皮膚の折れ・髪との境界は判断できない。**実素材の継ぎ目の品質と素材ごとの可動域は未確認としてAT-15へ渡す。**
