## 約束

**指の伸び・曲がり**：手基準の3D（`worldLandmarks`、手原点のm）で、指ごとに「手首→指先 ÷ 手首→付け根」を測る。1.4以上を伸び、1.15以下を曲げとし、間は決めない。画面の上下（指先が付け根より上か）は使わないので、上・横・斜め・下向きや、掌を横・裏へ回した手でも同じ値になる。3Dの点が無いときは肩の座標の点（奥行きは目安）で測る。

閾値はAT-01の2回の収録の分布から決めた（案内どおりの区間・案内の側の手）。下の値は、手形と指の組ごとのp10〜p90の範囲を合わせたもの。

| 指の状態 | 人さし指   | 中指       | 薬指       | 小指       |
| -------- | ---------- | ---------- | ---------- | ---------- |
| 伸び     | 1.53〜1.94 | 1.66〜2.12 | 1.61〜1.95 | 1.61〜1.89 |
| 曲げ     | 0.70〜0.98 | 0.73〜1.00 | 0.59〜0.95 | 0.72〜1.01 |

伸びはパー（2回目）・指さし・ピースで伸ばした指、曲げはグー・指さし・ピースで曲げた指。1回目のパーは案内に従っていないフレームを含み、p10が0.98〜1.12まで下がる。カメラへ向けた人さし指は短く写り、p10が1.08（伸びが決まらない）。

AT-01の試作の判定（付け根→第2関節→指先の曲がりの角度が45°未満で伸び、75°超で曲げ）では、2回目の右の真横の指さしの一致が1%だった（[AT-01報告](AT-01-inference.md)）。この比では同じ区間の候補が139／140で指さしになる（下の参考）。

**4種類**：人さし指・中指・薬指・小指の伸び／曲げの組で決める（親指は使わない）。

| 形      | 人さし指 | 中指 | 薬指 | 小指 |
| ------- | -------- | ---- | ---- | ---- |
| `open`  | 伸び     | 伸び | 伸び | 伸び |
| `fist`  | 曲げ     | 曲げ | 曲げ | 曲げ |
| `point` | 伸び     | 曲げ | 曲げ | 曲げ |
| `peace` | 伸び     | 伸び | 曲げ | 曲げ |

**既成の手形**（SDKの `Open_Palm`・`Closed_Fist`・`Pointing_Up`・`Victory`、確かさ0.7以上）は補助にする。4本とも決まれば指の形で決め、既成の手形が一致すれば確かさを0.2上げる（`Pointing_Up` でも指の形がパーならパー）。決まらない指があるときだけ、決まった指と矛盾しない既成の手形を使う（確かさ×0.6）。`Pointing_Up` は上向きしか表さない（AT-01：横向きで0〜1%）ので、横・斜めの指さしは指の形で決まる。4種類のどれでもない組（人さし指と小指だけ伸ばす等）はunknown。

**開始と維持の閾値**：確定している形のままかどうかは、緩い閾値（伸び1.3以上・曲げ1.25以下）で見る。新しい形の候補には通常の閾値（1.4・1.15）が要る。境界を揺れる指で、確定した形がunknownや別の形へ跳ばない。

**切替の安定化**：新しい候補が撮影時刻で120ms（`ARM_TIMING.shapeStableMs`）続いたら確定する。最初の形も同じ。別の候補・unknown・手が見えない／所属が決まらない観測・200msより空いた観測で、続きは途切れる。フレーム数では数えないので、15／30／60fpsのどれでも変化から133ms（120ms以上で最初のフレーム）で切り替わる。

**unknown**：新しい形にしない。確定した形と `confirmedAt` を変えない（`confirmedAt` は確定した形を最後に観測した撮影時刻）。長く続いたときの休止形への復帰はAT-09。

**掌の軸**：手首→中指の付け根の向き（肩の座標の単位ベクトル、外向き+x・下+y）。指先は使わず、グーでも同じ点を使う。切替待ちの間も毎回の観測から出す（手形の待ちで腕・手首を止めない）。肩の座標（腕の長さ1）で0.05より短い、または手基準の3Dで画面から60°より奥行きへ傾いた（画面上の長さが3Dの半分未満）ときは `null` にし、`axisObservedAt` を進めない。傾きを画像のzで見ないのは、AT-01でカメラへ向けた指さしの掌の軸が、画像のzでは画面とほぼ平行（3Dに対する比 p50 0.93）、手基準の3Dでは0.49だったため。

**指さしの向き**：人さし指の付け根→指先（`pointDirection`）。掌の軸とは別の値で、候補が指さしのときだけ返す。潰れていれば `null`。

**リセット**：新しい世代の観測が来たら両側の履歴を捨てる。`reset(g)` の後は g より古い世代を受け付けない。ミラーを変えると、モデルの各側に割り当たる演者の手が入れ替わるので、両側の履歴（確定した形も）を捨てる。同じか古い撮影時刻の観測は受け付けない。左右は独立。

**有効性**：結果の `validity` は手の観測のまま（`valid`・`inferred`）。`missing`・`ambiguous` の手は候補を空にし、確定した形を保つ。

## 契約との差（COへ）

- CC-032の `HandShapeCandidate`・`HandShapeResult` に指さしの向きの欄が無い。カードの「指さしの指方向は別の値」は、`HandShapeResult` を広げた `HandShapeEstimate.pointDirection` で返している。AT-08・09が指さしの向きを手首に使うなら、契約へ移すかをCOが決める。
- `HandShapeTracker` にミラーの設定が無いので、`configure({ mirror })` を実装側に足した。統合（AT-12）でミラーの変更を伝える必要がある。

## 未確認・制約

- 実カメラの点列は1人・1回の収録。左手のピース・左手で上を指す区間は案内どおりでなかった（または無い）ので、実カメラの例が無い（合成した手だけ）。
- 「4種類を左右別に各10回」の切替成功率・静止中の誤切替は未測定（AT-16）。暗い・遠い・手袋・別の人の手は無い。
- カメラへ向けた指さしは弱い。SDKが手を見つけないフレームが多く、人さし指が短く写って伸びが決まらない・向きが潰れる。短い不明は直前の形を保ち、長い場合はAT-09の休止形へ戻す。
- 親指は使わない（親指を立てたグーはグー）。ピースの指の開きは条件にしていない（人さし指と中指を揃えて伸ばしてもピース）。
- 閾値（1.4・1.15・1.3・1.25・0.05・60°・120ms・200ms・既成の手形0.7）は試作の開始値で、実カメラの長い点列で調整する（AT-14・16）。
- 手形の遅延は切替の待ち（約133ms）だけで、推定の遅延は含まない。軽量モード（手15fps）の実機での手形の遅延はAT-14で測る。
