# AT-12 顔・腕・手と既存スタジオの統合（設計）

2026-11-01 CL。[AT-12 カード](cards/12-runtime-integration.md)の設計。依存の7カード（AT-04・05・07・08・09・10・11）は、CO と CL の両方の確認が揃った版を使う。手順の多い統合なので、末尾の「決めてほしいこと」の答えをもらってから実装する。**同日、ユーザーが4項目とも推奨（A）で進めると判断し、実装した（[報告](reports/AT-12-integration.md)）。**

## 解決したいこと

カードの目的：独立して作った認識・関節・画面を既存のスタジオへつなぎ、保存した設定とモードの切替を含めて一続きに動かす。

1. カメラの映像 → 体の推定（AT-04）→ 左右の対応付け（AT-05）→ 手形（AT-07）→ 腕の追従（AT-09、IK は AT-06）→ 共通の評価（AT-08）→ プレビュー・出力ウィンドウ・Spout2 が、同じ姿勢と手形になる。
2. スタジオの「腕・手」（AT-11）が本物のサービスで動き、設定は Project、校正は Environment に保存される。
3. 停止・再開・カメラ・ミラー・プロジェクト・校正の切替で、古い履歴が残らず、顔・表情・アニメーション・物理・音声の動きを変えない。

## 考え方

### 腕のサービス（`services/arms/`、新規）

`createArmService` が `ArmService`（CC-032 v3）を実装し、部品を1つにまとめる。

```
tracking.body.onFrame ─▶ 対応付け（AT-05）─▶ 左右の手形（AT-07）─▶ 追従（AT-09：IKはAT-06）
                                    │                                       │
                                    └─▶ 校正の点を集める（AT-05）            └─▶ 腕の層（tick）
status / diagnostics ◀─ 体の推定の状態・追従の状態・リグの診断
```

- **体の推定を動かす条件**（判断2）：カメラを開始していて、左右のどちらかを入れていて、その側にモデルの腕の設定（有効なリグ）があるときだけ `body.configure({ enabled: true, ... })`。それ以外は止める（顔の推定は今のまま）。
- **校正**：`captureCalibration(step)` で約1秒ぶんの点を集め、4手順目で `computeArmCalibration` を求めて Environment へ保存する。`cancelCalibration` で途中の記録を捨てる。
- **診断**：最後の通知の生の点、対応付けの結果、追従の目標と実際の手首（モデルのリグから求める）、制限の理由を `diagnostics()` で返す。
- **寿命**：スタジオの実行部につないでいる間だけ購読し、外したら購読をやめる（二重に購読しない）。

### 層の合成

- 腕の層は、顔の層と同じ id `tracking` の producer を**別に**登録する（LAYER_ORDER では顔の層の後）。腕のパラメータ（肩・肘・手首・4手形）だけを左右別に出し、顔の層の重みや `detected` で止めない。
- 入れていない側・リグの無い側は値を出さない。表情・アニメーションは今どおり腕の層より上なので、腕を上書きできる。
- **上書きが終わったとき**：前のフレームで表情・ホットキー・アニメーションが腕のパラメータを上書きしていて、今のフレームで無くなった側は、表示していた姿勢（前のフレームの合成後の値）から追跡へつなぐ。AT-09 の `reset` は両腕を休止へ戻すので、上書きされた側だけを「表示中の姿勢からつなぐ」入口を AT-09 の実装に足す（契約は変えない。AT-09 は CL のカード）。
- 合成後の制約は AT-08 の共通評価が必ず掛ける（ここでは何もしない）。

### 設定・リセット

| きっかけ                         | 動き                                                                                                                     |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 画面で設定を変えた               | `Project.armTracking` を書き換える（判断1：Undo の対象にする）。追従・体の推定へすぐ反映                                 |
| プロジェクト・モデルが変わった   | 追従の `configure`（リグが変わった側は休止から始め直す）。体の推定の条件を見直す                                         |
| カメラの停止・再開・カメラの変更 | AT-04 が世代を上げる。各部品は古い世代を捨てる。停止中は、腕は保持 → 休止へ戻ってから止まる（値は休止のまま）            |
| ミラーの切替                     | 対応付け・手形の `configure`、追従の `reset`（表示中の姿勢から休止を経て、反対の手で再取得。いきなり左右を入れ替えない） |
| 校正のやり直し・未校正に戻す     | 対応付けの `configure`、追従の `reset`                                                                                   |
| スタジオから離れた               | 購読をやめ、体の推定を止める                                                                                             |

### 登録

- スタジオの「腕・手」（AT-11 の `register()`）を `modes/studio` の登録で呼ぶ。モデリングの「腕の設定」は登録済み。
- 開発用の確認の入口（仮サービス）は消す（判断3）。

## 契約・保存の形

変えない（CC-032 v3 の `ArmService`・`ArmMotionSession` などを使う）。AT-09 の実装に「上書きされた側だけ表示中の姿勢からつなぐ」入口を足すのは、契約の外の実装の追加。
