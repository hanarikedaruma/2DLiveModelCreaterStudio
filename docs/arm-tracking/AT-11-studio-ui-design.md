# AT-11 スタジオの腕・手の画面（設計）

2026-11-01 CL。[AT-11 カード](cards/11-studio-ui-calibration.md)の画面の設計。元の設計は[腕・手のトラッキング設計 §9](../arm-tracking-design.md#9-画面と準備の流れ)。手順の多い画面なので、末尾の「決めてほしいこと」の答えをもらってから実装する。**同日、ユーザーが推奨どおり（8項目とも A）で進めると判断し、実装した。設計との違いは[AT-11報告](reports/AT-11-studio-ui.md#実装で決めたこと設計との違い)。**

## 解決したいこと

カードの目的：腕追従の準備、左右の校正、手形の自動／固定、認識の状態確認をユーザーが行えるようにする。設計 §9 の流れを、次の4つにまとめる。

1. 腕・手の追従を左右別に入れ、動きの大きさ・なめらかさ・手形（自動／4種類の固定）を変えられる。
2. 準備が足りないとき、何が足りないか（「右腕の設定が無い」等）を具体的に示す。
3. 肩・肘・手首が写る位置へ案内し、楽な姿勢 → 肘を軽く曲げる → 左手を上げる → 右手を上げる、の4手順で腕を校正する。写っていない肘で校正を終えない。
4. 左右それぞれの状態（追従中／肘を補っている／手を見失っている／休止中）を示し、原因を調べるための詳細（生の点・採用した点・目標と実際の手首・制限の理由）を畳んで置く。

## 考え方

### 置き場所と通常の画面

「スタジオの設定」に「腕・手」のセクションを足す（顔のキャリブレーション・動きのすぐ後）。通常の画面には、設計 §9 のとおり、左右の有効・動きの大きさ・なめらかさ・手形だけを置き、点や理由は「詳細」に畳む。

```
腕・手
  [✓] 左腕（あなたの右手）   [ ] 右腕（あなたの左手）     ← ミラーONのとき。OFFなら同じ側の手
  ⚠ 右腕：モデルに腕の設定が無い（モデリングの「腕の設定」で作る）
  ・ 腕を校正していない（しなくても動くが、腕の長さは目安になる）
  [腕の校正]  [未校正に戻す]
  左腕：追従中・パー        右腕：オフ
                 左腕            右腕
  動きの大きさ  ──●────  1.0   ──●────  1.0
  なめらかさ    ───●───  0.5   ───●───  0.5
  手形          [自動 ▾]        [自動 ▾]        ← 固定しても腕は追従する
  ▸ 詳細（認識の状態・点・制限の理由）
```

- 左腕・右腕は**モデルの**左右（保存の L／R）。どちらの手で動くかを、ミラーに合わせて括弧で書く。
- 「準備」の行は、足りないものがあるときだけ出す。追従できない理由（⚠）と、できるが勧めること（・）を分ける。
- 手形を固定しても腕は追従することを、手形の選択の近くに短く書く。
- 狭い画面（800×600）では、左腕・右腕の2列が並ばなければ縦に積む。

### 準備が足りない項目

上から順に、該当するものを全て出す（1つ直すと次が見える、にしない）。

| 項目                                 | 判断に使うもの                                                | 出す言葉の例                                                     |
| ------------------------------------ | ------------------------------------------------------------- | ---------------------------------------------------------------- |
| 腕の認識が使えない                   | `status.available`・`reason`・Pose の状態                     | ⚠ 腕の認識を使えない（理由）                                     |
| カメラのトラッキングが止まっている   | `status.tracking.pose.state === 'off'`                        | ・ カメラを開始すると腕が動く（トラッキングの［開始］）          |
| その側のリグが無い・無効・問題がある | モデルの `armRigs`・`status.rigIssues`（error）               | ⚠ 右腕：モデルに腕の設定が無い（モデリングの「腕の設定」で作る） |
| 手形の絵が無い                       | `rigIssues` の `hand-missing`（warning）                      | ・ 右腕：ピースの手の絵が無い（休止時の形で表示する）            |
| 校正していない                       | `service.calibration() === null`                              | ・ 腕を校正していない（しなくても動くが、腕の長さは目安になる）  |
| カメラが校正のときと違う             | 校正の `camera` と今のカメラ（AT-05の `calibrationMismatch`） | ・ カメラが校正のときと違う（解像度）。［校正し直す］            |
| 手の認識がオフ・失敗                 | `status.tracking.hands.state`                                 | ・ 手の認識が使えない（手形は休止時の形のまま）                  |

### 校正の流れ

顔の校正と同じ形のダイアログにする（手順の一覧・指示・3・2・1・やり直し・キャンセル）。違いは、位置合わせの骨格を出すことと、写っている点を手順ごとに確かめること。

```
┌ 腕の校正 ───────────────────────────────────┐
│ ①楽な姿勢 ②肘を軽く曲げる ③左手を上げる ④右手を上げる │
│ ┌──────────（カメラの縦横比の枠）─────────┐ │
│ │            ○ 顔                          │ │
│ │     ●━━━━━━━━━●  肩                      │ │
│ │    ╱             ╲                       │ │
│ │   ●               ●  肘（写らない点は ×）│ │
│ └──────────────────────────────────────────┘ │
│ 両肩 ✓  左肘 ✓  右肘 ×  左手首 ✓  右手首 ✓        │
│ 両肩と両肘が枠に入るように座り、腕を楽に下ろす       │
│                    3                              │
│                                  [キャンセル]     │
└───────────────────────────────────────────────┘
```

- 各手順は、3・2・1 のあと `captureCalibration(step)` を呼ぶ（集めて確かめるのはサービス。AT-05 の `computeArmCalibration` が肘の欠け・前腕と上腕の比・上げた手の左右の食い違いで完了させない）。
- 手順に要る点（楽な姿勢：両肩、肘を曲げる：両肩・両肘・両手首、手を上げる：上げる側の手首）が写っていないうちは数え始めない。「右肘が写っていない」と待つ理由を出す。
- サービスが失敗（`invalid`）を返したら、その理由を出して、その手順だけやり直せる。キャンセルで前の校正はそのまま残る。
- 「左手を上げる」は**演者自身の**左手（校正の左右は演者の左右）。
- 顔の校正の意味・手順・保存は変えない。

### 骨格の表示とミラー

推定の点（未反転の画像の0..1）を、カメラの縦横比の枠に描く。**スタジオのミラーに合わせて1回だけ**左右を反転する：ミラーON は鏡のように（演者の右手が枠の右）、OFF は反転しない。こうすると、枠の右に出る腕と、モデルが動かす腕（見る人から右に見える腕）が一致する。描画の変換は1か所に置き、点の取り込み・ラベル・ヒット位置で2回反転しないことを試験で確かめる。

### 状態と詳細

- 左右それぞれ：追従中／肘を補っている／手を見失っている（保持）／戻っている／休止中／オフ／使えない。手の状態（追従・保持・休止・固定）と今の手形も並べる。
- 詳細（畳む）：認識の状態（Pose・手の状態、使っている処理（GPU／CPU）、fps、落としたフレーム、古い結果）、通常／軽量の切替、左右の生の点・採用した点・目標の手首・実際の手首・制限の理由。診断の時刻が古ければ（例：0.5秒より前）「古い」と示し、値を薄くする。

### 手形を試す

校正の後に「手形を試す」ページを出す。パー・グー・指さし・ピースの見本を並べ、左右それぞれで認識できた形に印を付ける。全部そろわなくても閉じられる（成功の条件にしない）。手形の判定はAT-07、表示する形はサービスの状態（`motion[side].hand`）から読む。

### 顔の割り当てとの関係

腕の追従は顔の「トラッキングの割り当て」と独立にする（設計 §6：顔・左右の腕・左右の手形を別々に管理する）。割り当てを「無効」にしても腕は左右の設定で動く。その組み合わせのとき、腕・手のセクションに一行注記する。

## 契約に足りないもの（COへ依頼）

AT-03の `ArmService` だけでは、次の3つが作れない。契約はCOが直列で持つので、[AT-03 CLレビュー](reports/AT-03-cl-review.md)の形式でCOへ依頼する。届くまでは、AT-11の仮サービス（`modes/studio/arms/` の中）に同じ形を持たせて画面を作り、届いたら契約の型に置き換える。

| 足りないもの           | 使う所                           | 依頼する形（案）                                                                                                                                                                     |
| ---------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 今の設定の読み出し     | スライダー・手形・有効の今の値   | `settings(): ArmTrackingSettings`（`calibration()` と対）。画面は Project を直接読まず、サービスの境界だけで読み書きする                                                             |
| 校正の取り消し         | キャンセル・途中で閉じる         | `cancelCalibration(): void`。途中の手順の記録を捨て、前の校正を残す。数え中・集め中のキャンセルで、最後の手順が保存されないようにする                                                |
| 診断（点・理由・時刻） | 骨格の位置合わせ、詳細、古い診断 | `diagnostics(): ArmDiagnostics \| null` と購読。撮影時刻、画像の大きさ、Poseの肩・肘・手首（visibility）と手首の生の点、左右の採用した肘・手首と有効性、目標・実際の手首、制限の理由 |
