# STEP3 の実装計画（カード）

[STEP3 の開発方針](../step3-plan.md)を、カードに分けた実装計画。STEP3 は**改善**（今ある機能の不具合・使いにくさ・欠けを直す）だけを行う。機能の追加・拡張は STEP4 で行う（[STEP4 の方針と候補](../step4-candidates.md)、[STEP4 の実装計画](../step4/README.md)）。担当は **CL**（Claude Code）と **CO**（Codex）。

## 使い方

- 1枚のカードが1つの作業単位。カードのファイル（[cards/](cards/)）だけを読めば作業できるように書いてある。共通の約束はこの README に置く。
- 番号は STEP2 までのカード（01〜54）の続き。
- 着手・完了は下の「カードの一覧」の状態の欄で管理する。
- カードの「触ってよいもの」の外を変える必要が出たら、作業を止めて「計画を直すとき」に従う。
- 新しい開発環境・スクリプト・リモートは作らない。確かめるのは STEP2 までに作ったテスト・e2e・計測・ユースケーステスト（下の「使う確認の仕組み」）。

## 同じ作業フォルダで2人が進めるときの約束

CL と CO は、同じ作業フォルダ（`C:/Users/hanar/.claude/workspace/2DLiveModelCreaterStudio`）の main で作業する。

- **ブランチを切り替えない。** `git checkout`・`git switch`・`git stash`・`git reset`・`git clean` は使わない（もう一方の書きかけの変更が消える）。
- **自分のカードのファイルだけをコミットする。** `git add <パス>` でファイルを指定する。`git add -A`・`git add .`・`git commit -a` は使わない。コミットのメッセージの頭にカードの番号を書く（例: `カード63: キーを1つ消す`）。
- **書きかけでも、ほかのパッケージを壊さない。** 型やテストを壊す変更は、まとめて一度に入れる。
- **もう一方のカードのファイルでテストが落ちたら、直さずに担当に知らせる。** 自分の触ったパッケージのテストが通れば、自分のカードはコミットしてよい。カードを締める前に、全体（`pnpm test`）も通す。
- **アプリ・e2e・計測を使うとき**（`pnpm app:install`・`pnpm e2e`・`pnpm measure`・開発サーバー）:
  - `.cache/locks/main.lock` に「担当・カード・始めた時刻」を書いてから使い、終わったら消す。ロックがあれば待つ。
  - もう一方に書きかけの変更が無い（区切りまでコミットした）ことを確かめてから、アプリを作る。書きかけを含んだアプリで確かめた結果は使わない。
  - 開いているアプリ（live2d-studio.exe）を、ロックの持ち主に断りなく閉じない。

| -------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 単体テスト           | `pnpm test`（全体）・`pnpm --filter <パッケージ> test`（触ったパッケージ）、`pnpm typecheck`・`pnpm lint`・`pnpm format:check` |
| Rust のテスト        | `apps/desktop/src-tauri` で `cargo test`（Rust を触ったカード）                                                                |

## テストの分担

テストは、実装の担当ではない人が書く。CL のカードのテストは CO が、CO のカードのテストは CL が書く（一覧の「テスト」の欄。各カードの「テスト（担当: …）」の節に、書くテストがある）。

- **いつ書くか。** カードの着手と同時に、テストの担当もテストを書き始める。もとにするのはカードの完了条件と「テスト」の節で、実装のコードではない。
- **ファイル。** テストの担当が新しいファイルを作り、名前にカードの番号を入れる（例: `projectIO.c58.test.ts`・`recovery.c58.e2e.ts`、Rust はモジュールの名前に `c69`）。置き場は、確かめるコードの隣（実装の担当のフォルダの中）でよい。実装の担当は、このファイルを書き換えない。
- **実装が入るまで。** 同じ作業フォルダでほかの人のテストを落とさないよう、テストのファイルの頭で `describe.skip` にしてコミットする（「カード58 の実装待ち」と書く）。実装の担当は、実装ができたら skip を外す（相手のファイルで触ってよいのはこの1行だけ）。
- **落ちたら。** 実装を直す。テストのほうが完了条件と違うと思ったら、テストの担当に知らせ、テストの担当が直す。
- **ユースケーステスト。** CH・UC-CH（tests/usecase/changes.md）も、テストの担当が書く。
- **締める前に。** テストの担当が、完了条件のすべてがテストかユースケースで確かめられていることを見て、カードの「記録」に「テスト確認（担当・日付）」を書く。これが無いカードは「完了」にしない。
- **実装の担当のテスト。** 実装の担当も、直す前に失敗する回帰テストを今までどおり自分のテストに書く（相手のテストとは別のファイル）。

## どのカードにも共通の完了条件

- 実装の担当は、直す前に失敗するテストを先に書き、直したあとに通す（自分の回帰テスト）。
- テストの担当（相手）が書いたテストがすべて通り、テストの担当が「テスト確認」を記録に書いている。
- `pnpm format:check`・`pnpm lint`・`pnpm typecheck`・`pnpm test` が通る。Rust を触ったら `cargo test`。
- 画面を変えたカードは、Edge で 1440×1000 と 800×600 を見て、実行時のエラーが無い。
- 直した課題の確認が、tests/usecase/changes.md に CH と UC-CH としてある（テストの担当が書く）。
- 確かめた範囲と確かめていない範囲を、カードの「記録」に分けて書く。実機で確かめていないものを「完了」と呼ばない。
- 外へ通信しない（e2e の外への通信の確認が通る）。

## 状態

| 状態                         | 意味                                                             |
| ---------------------------- | ---------------------------------------------------------------- |
| 未着手                       |                                                                  |
| 着手（CL / CO）              | 担当が作業中。ほかの人は始めない                                 |
| 中断（理由）                 | 途中で止めた。「記録」に、どこまでやったか・次に何をするかがある |
| コミット済み・テスト確認待ち | 実装はコミットしたが、テストの担当の「テスト確認」がまだ         |
| コミット済み・実機待ち       | コードはコミットしたが、実機の項目が残っている                   |
| 完了                         | 完了条件がすべて確かめられた                                     |
| 見送り（理由）               | 行わないと決めた                                                 |

- 着手するときは、先に状態を「着手（担当）」にする（二重の着手を防ぐ）。
- 使用量の上限などで止まるときは、ほかのパッケージを壊さない所までコミットし、カードの「記録」に次にやることを書き、状態を「中断」にする。もう一方が引き継ぐときは、状態の担当を書き換えてから。

## 計画を直すとき

- 「触ってよいもの」の外を変える必要が出た: 作業を止め、そのファイルを持つカードの担当と相談する。持ち主がいないファイルなら、この README とカードを直してから進める。
- 改善のつもりで始めたが、新しい機能になると分かった: そのカードでは作らず、[STEP4 の候補](../step4-candidates.md)に書く。
- 方針の承認を求め直すのは、[開発方針](../step3-plan.md)の5章の場合だけ。

- 2026-10-07 CO（カード57の範囲の補足）: 100枚の取り込み後に、未割り当ての画像もキャンバスへ一度に渡してGPUへ上げる停止を確認した。Step3で持ち主のない `apps/desktop/src/shell/canvas/CanvasHost.tsx` の画像の受け渡し部分と、その回帰テストをカード57に追加する。キャンバスの操作・表示の変更は含めない。
