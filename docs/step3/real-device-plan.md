## 4. 準備（CO だけで行う）

### 4.1 コマンド

PowerShell で、リポジトリの直下で毎回:

```powershell
$env:PATH = "$PWD\.cache\bin;$env:USERPROFILE\.cargo\bin;$env:PATH"; $env:COREPACK_HOME = "$PWD\.cache\corepack"
```

### 4.2 アプリを作る時機とロック

1. アプリに入るファイルに、だれの書きかけも無いことを確かめる。何か出たら、その持ち主に区切りまでのコミットを頼んで待つ。CO 自身のカードの書きかけも同じ（stash は使えないので、区切りまでコミットしてから）。

   ```powershell
   git status --short -- apps packages fixtures tools ':(exclude)**/*.test.ts' ':(exclude)**/*.test.tsx' ':(exclude)apps/desktop/e2e'
   ```

2. `.cache/locks/main.lock` が無いことを確かめ、`CO / カード70 / <始めた時刻> / app:install・計測` と書く。あれば待つ。
3. 本番のアプリ（手の確認に使う）: `pnpm app:install`。置き先は `%LOCALAPPDATA%\Programs\2D Live Model Creator Studio\live2d-studio.exe`。動いていると上書きできない。
4. 計測用のアプリ（`VITE_E2E` のデバッグの版。`pnpm measure` が起動する）:

   ```powershell
   $env:VITE_E2E = '1'; pnpm --filter @app/desktop tauri build --debug --no-bundle; Remove-Item Env:VITE_E2E
   ```

   以後の計測には `--no-build` を付け、同じ実行ファイルを使う。

5. `git rev-parse HEAD`、2つの実行ファイルの SHA256（`Get-FileHash <パス>`）、作った時刻を控える（結果の「実施条件」に書く）。
6. 計測用のアプリ（`apps/desktop/src-tauri/target/debug/live2d-studio.exe`）は、CL の `pnpm e2e` で作り直される。計測の前に毎回 SHA256 が控えと同じかを確かめる。違えば、その版で測り直す（版を混ぜない）。ロックは使い終わったら消す。

### 4.3 データの保護

- 始める前に、アプリの設定のフォルダ `%APPDATA%\jp.co.globalsystems.live2dstudio` を `.cache/realdevice-<日付>/user-data-backup/` へ写す。
- 起動で復元の確認が出たら、「名前を付けて保存…」で `.cache/realdevice-<日付>/recovered-copy/` に保存してから進める（捨てない）。
- `fixtures/` のフォルダは直接開かない。写して使う。
- 終わったら、環境設定（environment.json）を確認のあとのままにするか、バックアップへ戻すかをユーザーに聞く。

### 4.5 OBS

- 設定 → 映像: 基本・出力とも 1920×1080、FPS 60。録画の保存先・形式・画質を控える。
- OBS の「映像キャプチャデバイス」（カメラ）のソースは［無効化］しておく。OBS が同じカメラを使っていると、アプリは `NotReadableError: Could not start video source` で開けない。
- シーン「実機確認」に「ウィンドウキャプチャ」を足す: ウィンドウ「出力」（2D Live Model Creator Studio）、キャプチャ方法「Windows 10（1903 以降）」、ウィンドウの一致優先順位「ウィンドウのタイトルに一致する必要があります」。フィルタ「エフェクトフィルタ → クロマキー」（色: 緑。前回は類似性 400・滑らかさ 80・流出低減 100）。
  - 前回、自動で別のウィンドウへ切り替わる設定のため、編集画面を録画してしまった。録画のたびに、始め・中ほど・終わりのフレームでモデルだけが映っていることを確かめる。
- 表示 → 統計 を開いておき、録画ごとに「エンコードのラグによりスキップされたフレーム」「レンダリングラグによりスキップされたフレーム」を控える（OBS の側の落ちとアプリの側の落ちを分けるため）。
- **Spout2 のプラグイン**: 入っていない。2026-10-08 にユーザーが導入を許可した。CO が次のとおり入れる。
  1. 入手元は配布元の公式の Releases だけ（GitHub の Off-World-Live/obs-spout2-plugin。ほかのサイトの写しは使わない）。リリースの説明で、OBS 32 に対応する版を選ぶ。対応する版が無ければ入れず、Spout2 の項目は「保留（OBS 32 に対応するプラグインなし）」。
  2. ダウンロードの前に、版・ファイル名・大きさ・入手元をユーザーに伝える（許可は済んでいる。記録のため）。落としたファイルは `.cache/realdevice-<日付>/` に置き、git に入れない。
  3. OBS を閉じてから入れる。Windows の管理者の確認が出たら、ユーザーに押してもらう。OBS 本体の更新はしない。
  4. OBS を起動し、「ソース → ＋」に「Spout2 Capture」が出ることを確かめる。
  5. 結果の「実施条件」に、版・ファイル名・SHA256（`Get-FileHash`）・入れた場所を書く。
  - プラグインは OBS に入れるもので、アプリは外へ通信しないまま（2章）。

## 付録: 計測の JSON の分析

`.cache/realdevice-<日付>/analyze.mjs` に置いて使う（`.cache` は git に入らない。リポジトリの道具にはしない）。短時間の計測の数字を出すだけで、長時間の判定はしない。

```js
// 使い方: node analyze.mjs <計測の JSON>
// pnpm measure の JSON（record の中に記録）と、計測の表示の［JSON に書き出す］の JSON（記録そのもの）の両方を読む
import { readFileSync } from 'node:fs';

const d = JSON.parse(readFileSync(process.argv[2], 'utf8'));
const record = d.record ?? d;
const s = record.summary;
const t = record.samples.renderTimes;
const gaps = t.slice(1).map((v, i) => v - t[i]);
const over = (ms) => gaps.filter((g) => g > ms).length;
const pct = (n) => `${n}（${((100 * n) / gaps.length).toFixed(2)}%）`;
const ms = (stats) => (Number.isFinite(stats?.p95) ? `${stats.p95.toFixed(1)}（${stats.samples} 件）` : '—');
console.log({
  記録の秒数: (record.durationMs / 1000).toFixed(1),
  描画の平均: s.render.avg.toFixed(1),
  '1%最低': s.render.low1.toFixed(1),
  トラッキング: s.trackingFps.toFixed(1),
  '遅延 p95': ms(s.latency),
  '母音処理→描画 p95': ms(s.vowelLatency),
  フレームの間隔の数: gaps.length,
  '16.7ms を超えた間隔': pct(over(1000 / 60)),
  '33.3ms を超えた間隔': pct(over(1000 / 30)),
  'メモリ 始め→終わり（参考）': d.memory ? `${d.memory[0].mb} → ${d.memory.at(-1).mb}` : '—',
  カメラ: record.environment?.cameraCapture ?? d.cameraCapture ?? '—',
});
```
