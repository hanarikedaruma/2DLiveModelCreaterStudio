## 別作業の生成物の扱い（提案・未適用）

ユーザーが別作業の生成物と指定した2パスだけを、アプリの保守対象ソースから除外する方法を推奨する。ファイルはその場所に保持し、生成したプロジェクトを整形・削除・コミットしない。

| 設定                                      | 追加するもの                                                   | 目的                                                                       |
| ----------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `.gitignore`                              | `/projects/` と `/fixtures/scripts/build-desktop-character.ts` | ローカルのプロジェクトと一時生成用スクリプトの誤コミットを防ぐ             |
| `.prettierignore`                         | 同じ2パス                                                      | 保存・バックアップ・プレビューの JSON と一時スクリプトを全体の整形から除く |
| `eslint.config.js` の既存の全体 `ignores` | `projects/**` と `fixtures/scripts/build-desktop-character.ts` | 一時スクリプトを保守対象ソースの依存規則の検査から除く                     |
| `fixtures/tsconfig.json`                  | `exclude: ["scripts/build-desktop-character.ts"]`              | 既存の fixtures スクリプト・テストの型検査を保ち、この1件だけ除く          |

`.gitignore` だけでは ESLint と TypeScript の対象は変わらない。lint・整形だけの除外でも型検査は直らない。fixtures 全体の除外、import 規則の無効化、JSX 設定の追加によってこの参照を通す方法は採らない。

今後この生成用スクリプトを製品の保守対象として残す場合は別コミットにし、desktop の内部コマンドへの直接参照をやめて共有の公開 API を使う形に直し、lint・型・整形を通す。その場合はスクリプトの除外を外す。ローカルプロジェクトの `projects/` は引き続き生成物として扱う。

提案の適用と CL の作業中テストの確定後に、通常の4つの全体コマンドを再確認する。その結果が揃ってから57・60・61・64・68を締め、課題の状態を更新する。62の差し替えPSDと画面確認は、それとは別に残る。
