## 作るもの・直すもの

1. **ユーザーと短く回す。** ユーザーの要らない確認は CO だけで先に行う。ユーザーに頼むのは、必須（カメラで動かす・OBS と60秒の計測・I-039 の目視）と、時間があれば行うもの（マイク・重ねた動き・操作感）に分けた短いセッション（実施計画の5章）。できなかったものは「保留（時間）」。I-039 はカード56 の比較画像とアプリの実際の動きで判定してもらう。I-054（ワープの後のメッシュの頂点のドラッグ）も見る。本物の PSD（Photoshop・CLIP STUDIO）は、あれば確かめ、無ければ保留。
2. **録画・計測は OK をもらってから。** OBS の録画、`pnpm measure`、計測の表示の［記録を始める］は、毎回ユーザーに何を・何秒・どこへ保存するかを伝え、OK をもらってから始める。
3. **記録する。** tests/usecase/results/ に今日の結果、docs/studio-check.md の記録の表に行を足す。計測の JSON は docs/measurements/ に置く。長時間の耐久・メモリは「対象外（今回）・未実施」と書く。
4. **I-005 の判断。** OBS の録画と同時の60秒の計測の 1%最低の値と、録画でフレーム落ちが見えるかで、カード71 を行うかを決める。行わないなら理由を書き、カード71 の状態を「見送り」にする。
5. **NG の行き先。** NG は docs/issues.md の課題にし、STEP3 のどのカードで直すかを決める（入るカードが無ければ、改善なら新しいカードを足し、機能追加なら STEP4 の候補に書く）。
