# スタジオの実機の確認（カード24）

カメラでモデルを動かし、OBS へ出せることを手で確かめる手順。結果は下の「記録」に書く。

## 準備

1. アプリを起動する（`pnpm tauri dev`、またはインストーラーで入れたアプリ）。
2. モデルを用意する。どちらか:
   - 自分の PSD を取り込み、標準パーツへ割り当てて [かんたんセットアップ] を押す。
   - 開発中なら、メニュー「サンプルモデルを開く」→ 右の「標準パーツの割り当て」の [かんたんセットアップ]。
3. 上の [スタジオ] を押す。

Windows の「設定 → プライバシーとセキュリティ → カメラ」で「デスクトップ アプリがカメラにアクセスできるようにする」がオンになっていること。

OBS などが同じカメラを使っていると、アプリ側で `NotReadableError: Could not start video source` になる場合がある。OBS の「映像キャプチャデバイス」のプロパティでカメラを一時的に [無効化] し、アプリの [開始] を押し直す。OBS ではアプリの出力ウィンドウを取り込む。

## 手順

### 1. カメラでモデルが動く

1. 右の「スタジオの設定 → トラッキング」でカメラを選び、[開始] を押す。状態が「検出中」になる。
2. 顔を自分の右・左に向ける、上・下を向く、首を傾ける。モデルが同じように動く。
3. まばたきする、口を開ける、視線を左右に動かす。モデルの目・口・瞳が動く。
   - 左目だけ閉じて、モデルの画面で同じ側（ミラーがオンなら鏡のように見える側）の目が閉じるか見る。逆なら packages/tracking/src/source/convert.ts の `BLENDSHAPE_SIDE_OF_USER` を入れ替える。

### 2. ミラーのオン・オフで向きが入れ替わる

1. ミラーがオン（初期値）で、自分の右を向く → モデルは画面の上で鏡のように（画面の右へ）向く。
2. ミラーをオフにして同じことをする → 向きが逆になる。
3. アプリを再起動しても、ミラーの設定とカメラの選択が残っている。

### 3. 外れたときに正面へ戻り、戻ってくる

1. 検出中にカメラを手で覆う。
2. 約0.5秒はそのまま止まり、そこから約1秒かけてモデルが正面へ戻る。状態は「外れている」になる。
3. 手を外すと、約0.3秒でカメラの動きに戻る。状態は「検出中」になる。

### 4. OBS へ出す（単色の背景とクロマキー）

1. 「背景」で [緑] を押す。
2. 「出力」で解像度（1920×1080）を選び、[出力ウィンドウを開く] を押す。別のウィンドウにモデルだけが出る。
3. プレビューと出力ウィンドウが同じ動き・同じ配置になっている。プレビューでモデルをドラッグ・ホイールすると、出力ウィンドウもついてくる。
4. OBS で「ソース → ＋ → ウィンドウキャプチャ」を足し、ウィンドウに「出力」（2D Live Model Creator Studio）を選ぶ。キャプチャ方法は「Windows 10（1903 以降）」。
   - 「ウィンドウの一致優先順位」は「ウィンドウのタイトルに一致する必要があります」にする。別のウィンドウへ自動で切り替わる設定では、出力を開く前に編集画面を拾い、その後も編集画面を録画し続ける場合がある。モデルだけが映っていることを確認する。
5. ソースを右クリック →「フィルタ」→「エフェクトフィルタ → ＋ → クロマキー」（色: 緑）。背景が抜け、モデルだけが残る。縁に緑が目立って残らない。

### 5. 外へ通信しない

自動のテスト（`pnpm e2e` の apps/desktop/e2e/tracking.e2e.ts）で確かめている。カメラで推定を65秒動かしても外のサーバーへ1つも届かず、試しに外へ通信すると CSP に拒まれる。手で確かめるなら、トラッキング中に Windows の「リソース モニター → ネットワーク」で `live2d-studio.exe` と `msedgewebview2.exe` の送信先に外のアドレスが無いことを見る。

### 6. 基準PCでプレビューが 60fps

Ctrl+Shift+D で計測の表示を開き、トラッキング中のスタジオ画面のフレームレートを見る。基準PC（6コア12スレッド級・RTX 3060 級・16GB）で、OBS の 1920×1080・60fps 録画と同時に行う。

コマンドで記録する場合は、顔をカメラに映して `pnpm measure -- studio` を実行する。スクリプトは別のアプリを起動するので、手動確認用アプリのトラッキングを先に止めてカメラを解放する。結果の遅延サンプル数が0なら、顔ありの遅延は未計測。表示される遅延はトラッキングの時刻からアプリ内の描画までで、OBS 録画までの総遅延ではない。

### 2026-10-04 の再開確認

- 前回の計測コマンドは最終的に成功していた。JSONの描画154.2fps・追跡12.9fps・遅延p95 15.9msを確認。ただし前回録画の400秒地点には編集画面が映っていたため、「モデルのみの出力を録画した性能評価」としては採用しない。OBS録画負荷をかけた参考値として保持する。
- 今回のアプリは2026-10-03 20:59:39更新のデバッグ実行ファイルで、STEP1の操作項目も含む。前回のMVP計測時と同一ビルドではない。
- 起動時に基準モデルの作業を復元。eMeetの選択とミラーONは保持されていた。左右の向き・口・目の追跡入力値の変化を確認したが、実際の顔とモデルの左右・片目の対応の合否は利用者の回答待ち。
- OBSのタイトル一致を厳密にして、編集画面から「出力」へ取り込みを修正した。録画は `C:/Users/hanar/Videos/2026-10-04 00-43-22.mp4`（1920×1080、設定60fps、317.85秒）。録画停止とファイル確定をログで確認。270秒地点のフレームを見て、モデルだけが映り、目立つ緑の縁がないことを確認した。全フレームの検査ではない。
- プレビュー（1160×653）と出力（1920×1080）のモデル領域を、ドラッグ前・移動後・ホイール縮小後にピクセルで比較。正規化した外接矩形の差は各辺で0.004未満で、移動・拡縮が両方に反映された。確認用の操作はUndoで戻した。
- 実カメラの未検出時に追跡レイヤーの重みを観測。未検出直後と250ms後は1、500ms後は0.986、1000ms後は0.392、1500ms後は0。再検出後は0から100ms後0.273、200ms後0.741、300ms後1へ戻った。これは実際の未検出・再検出の観測であり、手でカメラを覆った操作との対応は利用者の回答待ち。
- ミラーOFFで左右角の符号が反転することを内部値で確認。見た目の反転は回答待ち。確認後はミラーONに戻し、観測用処理を外した。アプリは続きの目視確認用に開いたまま、OBS録画は停止済み。

### 2026-10-03 の計測（OBS 録画と同時・顔あり）

`MEASURE_OBS=1 MEASURE_LABEL=obs-face-rtx4050 pnpm measure -- studio`（60秒、出力ウィンドウ 1920×1080・緑背景、OBS で録画）。記録は docs/measurements/measure-obs-face-rtx4050-2026-10-03T11-03-15-256Z.json。

| 描画（平均 / 1%最低） | トラッキング                 | 遅延 p95（平均・最大、サンプル数） | メモリ           |
| --------------------- | ---------------------------- | ---------------------------------- | ---------------- |
| 154.2 / 45.5 fps      | **12.9 fps**（目標 30 以上） | 15.9 ms（12.7・22.6、681件）       | 1,064 → 1,145 MB |

トラッキングが 12.9fps なのはカメラが原因。アプリの中で、推定を動かさずにカメラから届く映像だけを数えた結果（MediaStreamTrack の stats と requestVideoFrameCallback で、6秒ずつ、OBS は止めた状態）:

| カメラ           | 1280×720（アプリが要求する解像度） | 640×480  | 1920×1080 |
| ---------------- | ---------------------------------- | -------- | --------- |
| eMeet C980 Pro   | 13.0 fps                           | 25.0 fps | 25.0 fps  |
| 内蔵の HD Webcam | 29.5 fps                           | –        | –         |

- どちらのカメラも設定上は 30fps を返すが、eMeet C980 Pro は 1280×720 のとき実際には毎秒13枚しか出さない。遅延の平均（12.7ms）から見て推定は1枚あたり 10ms 前後で、届いた映像をアプリが捨てることは無い。
- 25fps で頭打ちになるのは、部屋の明るさ（露出が長くなる）か、蛍光灯のちらつき対策（50Hz）の影響と見られる。評価条件は「明るい室内」。
- 遅延はトラッキングの時刻（推定を始めた時刻）から描画までで、カメラの中の遅れと OBS の録画までは含まない。
