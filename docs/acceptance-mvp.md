- 描画はスタジオの実行部のフレーム（requestAnimationFrame。画面のリフレッシュレートに合わせて回るので、この PC では約165fps）。
- トラッキングはカメラから届く映像の速さに張り付いている。内蔵の HD Webcam（1280×720 を要求）は 29.5fps。eMeet C980 Pro は 1280×720 では毎秒13枚しか出さない（640×480 と 1920×1080 では 25fps）。推定を動かさずにカメラの映像だけを数えても同じなので、アプリではなくカメラ側の速さ（docs/studio-check.md の 2026-10-03 の計測）。
- 遅延はトラッキングの時刻（推定を始めた時刻）からアプリ内の描画までで、カメラの中の遅れと OBS の録画までは含まない。
- 1%最低値（遅いほうから1%のフレームの平均）は 45fps 前後。推定がメインスレッドで同期に動くため、推定と描画が重なったフレームが遅くなっていると見られる。60Hz の画面なら1フレーム落ちる程度。

### 基準PCでの計測の手順

1. リポジトリを用意し、`pnpm install`。
2. OBS で 1920×1080・60fps の録画を始める。
3. カメラの前に座り、顔を写したまま `pnpm measure -- studio` を実行する（5分の記録は環境変数 `MEASURE_SECONDS=300`）。アプリが起動し、基準モデルを開いてスタジオでトラッキングを始め、記録を取る。環境変数 `MEASURE_OBS=1` を付けると、1920×1080・緑背景の出力ウィンドウを開き、顔が検出されるまで待ってから記録する（OBS でこのウィンドウを取り込んで録画する）。
4. 結果は apps/desktop/e2e/results/measure-*.json（要約は画面にも出る）。この表に足す。
5. アプリの中でも Ctrl+Shift+D で計測の表示を開き、[記録を始める] → [記録を止める] → [JSON に書き出す] で同じ形の記録を残せる。

気づいたこと（課題として [docs/issues.md](issues.md) で管理する）:

- 大きな PSD でメモリが多い。素材の置き場（createAssetRepository）が、素材ごとに ImageBitmap と ImageData（メッシュの生成用）の両方を持ち続けるため（I-003）。
- PSD の取り込みはメインスレッドで同期に動くので、大きな PSD では取り込みの間は画面が止まる（9秒、I-004）。
- トラッキングの速さがカメラ次第で、解像度を選べない（I-001）。カメラから届く映像の fps が画面で分からない（I-002）。
- 描画の1%最低が 45fps 前後（I-005）。
