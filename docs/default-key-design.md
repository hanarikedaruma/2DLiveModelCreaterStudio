# 既定値の位置も、そのパラメータのキーとして直す（設計）

2026-10-11 CL。課題は I-072。ユーザーが案D で進めると決めた（「いったん、現在の提案で進めます。なお問題があるようならば、根本解決を検討します」）。末尾の「決めてほしいこと」に答えをもらってから実装する。

## 解決したいこと

ユーザーの言葉:

> 輪郭線での編集の時とか、Aキーを編集して、Bキーを編集した時、Aキーに影響が出ている気がするんだけども、どうなっているか。多分メッシュ修正とか、ワープとか全般的に言えることだと思うが。

調べた結果（[I-072](issues.md)）:

- B が別のキー（−30・顔 上下 +30 など）なら、A は動かない（0px）。
- B が既定値（顔 左右 の行を選んだまま、正面 0）だと、A も B と同じだけ動く（メッシュ・輪郭線 12px、ワープ 10.7px）。

## 今の作り（コードで確かめたこと）

| 項目              | 今の作り                                                                                                                                                                                                               | 問題                                                         |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| キーの記録        | 基準の形からの差（`apps/desktop/src/services/keyEditor/points.ts`・`transform.ts`）                                                                                                                                    | —                                                            |
| 既定値での編集    | パラメータの行を選んでいても、値が既定値なら基準状態とみなし（`common.ts` の `isBaseState`）、基準の形（頂点・制御点・パーツの値）を直す                                                                               | 基準を直すと、すべてのパラメータのすべてのキーが同じだけ動く |
| 既定値のキー      | 差 0 の約束。バインディングを作るとき（`createBinding`）・かんたんセットアップ・奥行きで作り直す（`packages/core/src/generate/surface.ts`）は差 0 で作る。右クリックで消すと「デフォルト値のキーは基準なので消せない」 | —                                                            |
| キャンバスの帯    | 「編集中: 顔 左右 ＝ 正面（0）」。パラメータを選んでいないときは出さない                                                                                                                                               | 基準を直していることが分からない                             |
| 計算（evaluator） | キーの差をそのまま補間する。既定値のキーに差があっても、その差を使う（不透明度だけは既定値のキーとの差を使う。I-026）                                                                                                  | —                                                            |

## 考え方

- **記録先**（D1）: パラメータの行を選んでいる間は、値が既定値でも、そのパラメータのバインディングの既定値のキーに記録する（2つ選んでいれば、組み合わせのバインディングの (0,0) のキー）。基準の形は変えない。
  - 正面 0 で直しても、+30・−30 のキーは変わらない。0 と +30 の間は、直した 0 の形と +30 の形の間で補間する。
  - 別のパラメータとは足し合わせなので、顔 左右 = 0 で直した形は、顔 上下 を動かした姿勢でも（顔 左右 が 0 なら）見える。
- **基準の形を直すのは**、パラメータの行を選んでいないときだけ。今までどおり、すべてのキーが一緒に動く（元の形をまとめて直す）。
- **バインディングが無いとき**（D2）: 既定値のキー1つだけのバインディングを作る。どの値でもその形になる。ほかの値にキーを足すと、そこから別に直せる。
- **帯**（D3）: パラメータを選んでいないとき、キーのあるパーツを選んでいれば「基準の形を編集中（すべてのキーが一緒に動く）」と出す。
- **不透明度**（D4）: 今のまま。既定値では Part.opacity を直す（I-026 の「既定値のキーは基準の不透明度と同じ」を保つ）。
- **作り直し**（D5）: 「奥行きで作り直す」・かんたんセットアップの作り直しでは、既定値のキーの差を、作り直したすべてのキーに足す（既定値で直した形を保つ）。「間を生成」「すべて再補間」は、直した既定値のキーを手で直したキーとして残し、隣のキーとの間を作る（今の作りのまま動く見込み。曲面・回転の補間は確かめる）。
- **右クリック**（D6）: 既定値のキーに差があるときは「このキーの差を消す（基準の形に戻す）」を出す。差が無いときは今のまま「消せない」。
- **保存**: 形式は変えない。今のデータは既定値のキーが差 0 なので、見た目は変わらない。

### 見た目

```
顔 左右 の行を選び、正面（0）で頂点を動かす
  帯: 編集中: 顔 左右 ＝ 正面（0）
  → 顔 左右 の 0 のキーに記録。+30・−30 のキーは変わらない

パラメータの行を選ばずに頂点を動かす（キーのあるパーツ）
  帯: 基準の形を編集中（すべてのキーが一緒に動く）
  → 基準の形を直す。すべてのキーが一緒に動く（今までどおり）
```

## テストと確認

- 単体:
  - パラメータを選んで既定値で直すと、そのパラメータの既定値のキーだけが変わり、基準の形・ほかのキーは変わらない（メッシュの頂点・ワープの制御点・パーツの値）。2つ選べば組み合わせの (0,0)。
  - パラメータを選んでいなければ、今までどおり基準の形を直す。
  - バインディングが無いときは、既定値のキー1つのバインディングを作る。
  - 不透明度は今のまま。
  - 奥行きで作り直すと、既定値のキーの差が作ったキーに足される。既定値のキーの差を消せる。
- ツールを通して: 実際のモデルで調べたときと同じ手順（+30 を直してから 0 で直す）で、+30 の見た目が動かない（メッシュ・輪郭線・ワープ・選択・変形）。
- 全体: `pnpm test`・`pnpm typecheck`・`pnpm lint`・`pnpm format:check`。開発サーバーの画面で、帯と、+30 が動かないことを確かめる。

## 完成の条件

- 顔 左右 の行を選んだまま正面 0 で直しても、+30・−30 のキーの形は変わらない（メッシュ・ワープ・輪郭線・選択・変形）。
- パラメータを選んでいないときは、今までどおり基準の形を直し、帯でそれが分かる。
- 今のプロジェクトを開いても、見た目は変わらない。

## 採用した仕様（2026-10-12）

ユーザーの「次。アプリ版は都度更新してください」を受け、D1の案Dを維持し、D2〜D6は推奨仕様を実装した。KeyEditorの規則はCC-020として記録し、型と保存形式は変えない。担当はこの作業で設計と実装を確認した。基準判定と全既定値判定を分け、不透明度と流れ線の焼き込みの例外を保った。

右クリックで差を消す操作は選択パーツと子孫（選択無しなら全パーツ）の1軸バインディングを対象にし、不透明度とキー位置は維持する。戻したキーは手動/ロック済みとなり、Undoで戻せる。方向グリッド中央は2つの既定値の組のキーを編集すると表示する。

生成では手動/ロック済みの既定値の補正だけを新しいキーへ重ねる。既存の自動キーの過去の差は再生成する。回転・曲面の再補間と、既定値に非ゼロ差があるワープの範囲再調整は元の方式のまま保持でき、回帰テストで確認する。
