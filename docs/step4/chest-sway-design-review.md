同日の重力方向の指摘による修正は [胸揺れの重力と慣性の座標](chest-gravity-design.md)。gravity=0とパラメータ差分だけの旧候補を胸の既定とせず、モデル座標の重力・実際の体の移動による慣性・変換後に足す胸のキーを必須にする。重力・入力・キー・評価順は同文書を優先する。

## 結論と先行範囲

つなぎ目を留めた頂点の差分で上下・左右に弾ませる方式Aは採用できる。ただし、元の計画のままではつなぎ目の固定と設定の寿命を保証できない。以下の修正を実装条件にする。

- カード79の胸揺れに必要な契約だけを98の先行作業で直列に実装する。顔・舌・腕の入力の拡張やカード75の実測は待たない。現在の `Physics` に胸用の項目はまだ無い。
- カード74の複雑なモデルを待たず、胸を別レイヤーにした専用の小さな見本で数値・画面・比較画像を確かめる。
- 最初の対象は分けた画像パーツと方式A。方式Bは比較用の候補であり、比較前に既定へ入れない。体に描いた胸の範囲指定は、元の計画どおり別の条件付き範囲として残す。
- 体が傾いても重力を下向きに保ち、傾いた静止姿勢でも釣り合いを反映する。固定点は体へ追従し、胸の自由点への差分はモデル座標で体の変換・ワープの後に足す。従来のローカルの上下キーをそのまま使わない。
- STEP3の受け入れ、カード79の胸以外の契約、他のSTEP4カードの開始条件は変えない。CLの引き継ぎに従いCOが追加検証を行い、新しいCLの独立署名として扱わない。

## 体とのつなぎ目

### 体の動きを継承する

標準の胸は、同じ `bodyRoot` の下にあるだけでは足りない。接続先の胴体画像パーツの子にすると、胴体自身の位置・回転・拡縮と、その祖先のワープを継承できる。検討用の見本ではBreath=1の4.5pxの差が0pxになった。

- 標準の胴体が1つなら、そのパーツを接続先にする。複数の胴体画像や既存の独自の親があるときは、勝手に先頭の胴体へ付け替えず、対象を確認できるようにする。
- 胸の描画順は体より前、腕より後ろ。親子関係と描画順は別に扱う。既存のマスク・非表示・不透明度の継承も確認する。
- かんたんセットアップの階層作成でこの接続を戻さない。既に組まれた親と姿勢を変える場合は現在の基準姿勢を保てることを確認し、保てない構成へ自動で適用しない。
- 親の画像メッシュの頂点変形は、現行パイプラインでは子へ継承されない。胴体自身の独自のverticesキーによる変形まで、親子化だけで固定できるとは扱わない。

先行版の自動設定が保証するのは標準の体の移動・傾き・呼吸と、両者に共通の祖先の変形。胴体自身に独自の頂点変形がある場合は自動設定をそのまま適用せず、理由を表示する。体表面への三角形対応による取付けが必要なケースは別の対応範囲として明示する。M9の判定でもこの対応範囲を記録し、未対応の構成を「つなぎ目固定済み」としない。

### 固定する輪郭と滑らかな重み

旧式の `fh = smoothstep(0,0.2,s/幅)` のsは外接矩形の左右端からの距離であり、脇の曲がった輪郭までの距離ではない。

- 三角形の境界辺から輪郭を求める。既定では上端15%の帯を固定し、外側の輪郭も下端20%かつ横の中央60%に入る頂点以外を固定する。自由な下端中央の範囲を帯で調整できるようにする。穴の輪郭は固定し、複数の島は成分ごとに扱って1つの矩形として計算しない。
- 固定頂点の差分を厳密に0にする。固定辺からの距離を使って内部へsmoothstepで重みを増やす。自由な下端中央との境目でも重みを滑らかにする。
- 固定される帯・輪郭を画面で確認できるようにする。上下の帯と下端中央の自由な幅を簡単な調整で変えられるようにし、頂点を1点ずつ編集する操作を前提にしない。
- 上下6%・左右4%・最大16pxは初期の目安。薄い三角形や細い部分ではこの値だけで安全とは言えない。両方向を同時に端へ動かした形でも三角形が反転・潰れないよう、作成時に振れ幅を小さくできる。
- 方式Aの同じ重みを使う2方向の移動では、各三角形の面積はBustX/BustYに対して一次になるため、4隅での反転検査を生成時の条件にできる。既存の姿勢キーやワープと合成した完成形の確認は別途必要。
- メッシュ変更で固定頂点とキーの対応が失効したときは、黙って動かさず作り直しの理由を表示する。頂点数が変わらない位置変更も確認対象にする。

## 物理・出力・方式の規則

### 契約と旧データ

胸に必要な契約は `preset: 'chest'`、`deform?: 'swing' | 'bounce'`、`verticalOutputParameterId?: Id | null`、`inputs[].axis?`、標準パーツchestと、使うときだけ足すBustX/BustY。[重力の修正設計](chest-gravity-design.md)の `Physics.bounce`・`Binding.vertexSpace`・`TargetDeltas.modelVertices` と、実際の体の基礎の姿勢を渡すフレーム契約も先行範囲に含める。固定範囲・メッシュの対応・所有する自動バインディングの記録も、実装する形を契約段階で明確にする。

現在はschemaVersion 5。新しい種類と振る舞いを含むため先行実装で6へ上げ、5→6は胸設定を勝手に追加しない移行にする。旧データのdeform省略はswing、上下出力省略は旧出力、axis省略は両方。新しい入力や物理を持たないプロジェクトの値を変えない。

無い上下出力は読み込み時に外して知らせる。構造・数値の検証と参照切れの修復は分ける。schemaの読み込みで先に参照切れを拒否して、IOの修復へ届かなくなる作りにはしない。

### 出力を共有しない

- 1つの物理から左右と上下を別のパラメータへ出す。左右と上下に同じIDは指定できない。
- 最初の標準の胸でBustX/BustYを使う。既に他の物理や独自の設定が所有しているときは、上書きせず専用の出力2つを作る。追加の胸・通常の複製も専用出力を作り、元の胸の出力へぶら下げない。
- 出力IDを常に左右用・上下用として保つ。「上下だけ」でBustXをBustYへ付け替えない。上下出力がある新しい項目はverticalでも上下用へ出し、項目の無い旧verticalは従来の主出力へ出す。
- 入力にaxisを指定した場合、向きで絞った結果が空ならその向きの入力は0にする。別の向きの既定入力へ戻さない。省略した旧入力はこれまでどおり両方へ使う。
- 2つの出力自身を入力へ入れない。自動設定で別の胸の出力を入力へ使わず、計算の順番に依存する循環を作らない。

### 方式の切り替えとOFF

- 1パーツにつき既存のPhysicsの枠は1つ。軸での回転と胸の弾みはその枠の変形方法として切り替える。流れ線の揺れは独立した設定として保持する。
- 胸へ切り替えるとき、所有する自動の回転・曲げを外し、左右・上下の弾みを同時に作る。逆への切り替えも同様。物理・パラメータ・バインディング・履歴を1回のUndoで戻す。
- 「自動」の条件はsourceがauto/generatedで、すべてのキーが未lockedであること。manualやlockedがあれば、一方だけを変えて混在させず、方式切替を止めて理由を表示する。自分が所有していないバインディングを消さない。
- OFF・再実行・再生成で手で直したキーを消さず、他で参照される出力パラメータも消さない。利用判定と削除は両方の出力を見る。体との親子接続をOFFで勝手に解除しない。
- 通常複製と左右反転では、胸の設定・出力2つ・所有キー・固定範囲・重力の基準を対応させる。自動のmodelキーは反転した頂点対応へ作り直し、正のXがキャンバス右、Yが下の意味を維持する。ローカルの頂点差分と同じ反転を掛けない。従来の軸揺れの複製規則は別に保つ。

## 旧候補の入力と係数の確認

旧候補は、左右にBodyAngleX/Z・FaceAngleX、上下にBodyAngleY・FaceAngleY・Breathの変化を使っていた。実際の体の位置・速度を計測したものではなく、BodyAngleYは現行の標準セットアップで体を上下移動するキーでもない。重力の修正後はこの近似を胸の既定入力にせず、基礎の姿勢での胸の中心の実位置から慣性を求める。同じ動きをパラメータ差分で二重に加えない。

旧候補のspring=120・damping=5・gravity=0・inertia=1.5・range=1、strength=0.5は、現行エンジンでspring=96・damping=4となる。連続時間の線形の理論値では周波数は約1.53Hz、自由応答の包絡は1秒で約13.5%残る。次の数値は旧振り子による比較用であり、モデル座標の下向きの重力・実位置の慣性を追加した胸の既定値や収束の保証ではない。

現行エンジンを使い、正規化入力を0から2/3へ0.3秒のsmoothstepで1回動かし、その後止めた。収束は「以後の正規化出力がすべて±0.02以内」と定義した。候補の胸用係数を、既存のhair項目へ仮に与えた検討であり、胸の製品実装の合格記録ではない。

| 描画間隔 | 最大出力 | 入力停止1秒後以降の最大絶対値 | 入力停止から収束まで |
| -------- | -------- | ----------------------------- | -------------------- |
| 30fps    | 0.4254   | 0.0612                        | 1.60秒               |
| 60fps    | 0.4318   | 0.0616                        | 1.60秒               |
| 120fps   | 0.4325   | 0.0617                        | 1.60秒               |

小さい入力0→0.3では60fpsで約1.27秒だった。「2〜3回・約1秒で収まる」を確定値としない。候補値を出発点に、揺れの幅・収束・30Hzの入力段差・長い停止の後・端への張り付きを実装テストと比較画像で決める。より早く収める場合はdamping等の変更を同じ波形で比較する。

数値検討のコード・JSON・ログは `.cache/i061-design-review-2026-10-08.{ts,json,log}`。既存エンジンと標準の呼吸の計画・評価器・変形器を直接使った。アプリやプロジェクトは変更していない。

## 画面・流れ揺れ・出力との接続

- 設定は既存の「パーツの設定」を使う。軸の回転と胸の弾みを同じ「軸揺れ」という表示で扱わず、現在の方式が分かる名称・説明にする。胸の説明にピボットを根元へ動かす案内を出さない。
- 振り子はswingのパーツだけ。胸は単色の弾みの目印を別に用意する。風鈴と混ぜず、既存の狭い一覧の目・鍵・長い名前の領域を保つ。
- 数値欄のrangeは、swingでは従来のラジアン、bounceでは正規化した弾みの範囲として説明する。胸の「重力の強さ」はbounce専用の0..1の設定（既定候補0.3）とし、振り子のgravityの数値と混ぜない。体が傾いてもキャンバス下向きであることを説明する。
- 揺れのお試しは左右・上下を別々にも同時にも試せる。元の値を復元し、選択変更・方式変更・プロジェクト変更で止める。設定を表示するパレットの寿命と物理の寿命を結び付けない。
- スタジオで物理を1回進めた完成形をプレビューと全出力で共有する。肩との接触には胸を含む完成形の体を使う。髪の軸揺れの中立評価はswingだけを対象にしてbounceを消さない。
- アニメーション画面は現在、流れ揺れのセッションを進めるがPhysicsのproducerは進めていない。手で付けたBustX/Yキーの表示と、実行時の自動胸揺れを区別する。先行版で自動胸揺れを再生プレビューへ足すなら専用の物理セッションを持ち、シーク・ループ・停止・モデル変更で初期化する。流れ揺れだけから動作を推測しない。
- 方式Bの「体積を保つ」は2Dメッシュの式だけでは保証できない。比較する場合は「面積の変化を抑えた補助変形」とし、式・反転検査・固定点の条件を別に決める。

## 実装順と追加する検証

弾みの重み・キーの生成と胸の既定係数はcoreの純粋関数として共有する。desktopの設定とcoreのかんたんセットアップで別々に実装せず、coreからdesktopへの依存も作らない。セットアップのID予約には新しく作る物理・出力パラメータも含め、再実行で重複作成しない。

1. 胸だけの契約と移行、両出力の修復・利用判定・削除、重力の基準、モデル座標のキーと差分を実装する。他のSTEP4契約と混ぜない。
2. 純粋な弾みのmodelキー生成と胴体への接続、固定帯、薄い/曲がった輪郭、メッシュ変更時の保護を作る。矩形だけで固定のテストを済ませない。
3. 胸用のモデル座標の重力・実際の体の動きによる慣性・基準姿勢の釣り合い・2出力、お試し、方式切替・OFF・Undo/Redo、複製・反転・保存・再読込をつなぐ。
4. 標準パーツの割り当て・描画順・再実行に接続する。胸の無いモデルのモデル・物理・パラメータを既存結果と比較する。
5. 軸/胸の目印、髪の中立評価、肩の完成形、スタジオ/アニメーション/出力のセッションを確認する。Edge/Nativeの1440×1000と800×600で操作する。
6. 専用の見本で静止姿勢と時系列を比較し、自然さと方式Bの採否はユーザーの目視として残す。

追加する条件は、傾いた静止時の釣り合い、重力方向、基準姿勢の二重の垂れ防止、実位置の横・上下・回転・呼吸、拡縮・反転・ワープ時の方向とつなぎ目、曲がった脇の固定、両出力の同時駆動、2つの胸の異なる設定、lockedの自動キー、方式切替の取消、片方の出力削除、再読込、複製と反転、頂点数が同じメッシュ編集、既存の髪のbothの一致、同一フレームの再表示、停止後の復帰。詳細な数式・確認済みの42条件・実装後のテストは [重力の修正設計](chest-gravity-design.md)。未対応の体表面の頂点変形も理由表示まで確認する。
