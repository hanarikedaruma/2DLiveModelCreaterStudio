# STEP4 の実装計画（カード）

[STEP4 の方針と候補](../step4-candidates.md)を、カードに分けた実装計画。STEP4 は**機能の追加・拡張**を行う。始めるのは STEP3 の受け入れ（カード72）の後。担当は STEP3 と同じく **CL**（Claude Code）と **CO**（Codex）。

2026-10-31: 腕・手の追加要望について、[専用の実装計画と16枚のカード](../arm-tracking/README.md)（AT-01〜16）を作成した。肩・肘・手首、固定した掌面、4種類の手形、自然なロスト・復帰を扱う。腕分の順序・担当・共有ファイルの所有は専用計画を参照する。現在は計画のみ・全て未着手。他のSTEP4の範囲とSTEP3の受け入れ状態は変更していない。

2026-10-08: ユーザーが I-063 / 候補 #17 の[設計案](curve-guide-design.md)を実装するよう指示したため、[カード99](cards/99_curve-guide.md)として先行着手（CO）。このカードだけは72/73の待ちを解除し、契約CC-011も99で直列に行う。STEP3は未受け入れのまま、他のカードの開始条件は変えない。CLの残作業の引き継ぎに従い、COが実装と追加テストを行う。カード92の時間の補間の曲線とは別の機能。

同日の追加設計: [髪の慣性・肩との接触](hair-dynamics-design.md)。99の静止線を基準にする揺れ・肩の取付け・接触・セッション・保存・検証を具体化し、その後の追加指示でカード100へ実装した。

その後の実装指示と、肩接触も今回対象・衝突判定をON/OFFする指定により、[カード100](cards/100_flow-sway.md)を先行実装（CO）。流れ揺れ・肩接触・軸との合成・風鈴を含む。契約はCC-013で直列に行い、他のSTEP4カードの開始条件とSTEP3の受け入れ状態は維持する。

名称は［軸で揺らす］［流れ線で揺らす］。同じパーツで軸揺れと流れ揺れを併用し、ON/OFF・調整・保存を独立させた。重力補正が軸の動きを消さない評価順と、片方をOFFにしたときの保護も実装した。[パレットの表示設計](../modeling-palette-design.md)に合わせ、軸は「パーツの設定」、流れはツール選択時の「流れ線」に配置する。

胸揺れの先行方針（2026-10-08）: ユーザーの指示で[カード98](cards/98_chest-sway.md)の設計を現行コードと再照合した。[設計再確認](chest-sway-design-review.md)の体への接続・輪郭固定・2出力の所有・方式切替・既存の軸/流れとの判定を実装条件にする。79の胸に必要な契約だけを98内で直列に扱い、74を待たず専用の見本を使う。方式A・分割パーツの製品実装とschemaVersion 6への移行をカード98で実装済み（2026-10-09、CC-014）。画面と実IOの自動確認済み。自然さ/方式選択は目視待ち。他のSTEP4の開始条件とSTEP3の受け入れ状態は維持する。

同日の重力方向の指摘による [修正設計](chest-gravity-design.md): 体が傾いても重力はモデルのキャンバス下向き、慣性は体の実位置から計算し、傾いた静止姿勢も釣り合いを反映する。胸の頂点差分は体の変換・祖先のワープ後にmodelの座標で足す。重力の保存した基準・モデル座標のキー・評価器/変形器の適用段階・フレーム契約を98の先行範囲へ追加する。旧gravity=0の候補は胸の最終の既定値にしない。

パーツ一覧の目印は、軸揺れを振り子、流れ揺れを風鈴で示す。どちらも模様なしの単色線画で、両方ONのパーツには振り子→風鈴の順で並ぶ。片方のOFFや停止理由はその方式のアイコンだけへ反映する。軸の振り子は[99の追補](cards/99_curve-guide.md)、流れ揺れ・風鈴・両方式の合成・独立した肩接触は[100](cards/100_flow-sway.md)で実装した。利用者の制作モデルの自然さとCLの独立確認は残す。

## 使い方

- 進め方の約束は [STEP3 の README](../step3/README.md) と同じ。特に次の節をそのまま使う: 「同じ作業フォルダで2人が進めるときの約束」「テストの分担」「使う確認の仕組み」「どのカードにも共通の完了条件」「状態」「計画を直すとき」。
- 1枚のカードが1つの作業単位。カードのファイル（[cards/](cards/)）だけを読めば作業できるように書いてある。番号は STEP3（55〜72）の続き。
- **テストは相手が書く。** CL のカードのテストは CO が、CO のカードのテストは CL が書く（一覧の「テスト」の欄と、各カードの「テスト（担当: …）」の節）。
- **条件付きのカード**（77・81・91〜96）は、カード73 でユーザーと「行う」「見送り」を決める。見送りのカードは状態を「見送り（理由）」にし、依存の表から外す。
- 新しい開発環境・リモートは作らない。新しい機能の依存（zip・姿勢の推定のモデルなど）も、外へ通信しないものだけを同梱する。
