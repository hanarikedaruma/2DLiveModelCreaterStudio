自動テストで確かめた範囲と、実機での見た目・操作・基準PCの性能は分けて書く。各カードのテストの詳細は docs/status.md の STEP1 の節、見つけた課題は docs/issues.md。

## 結合でしたこと

- `apps/desktop/src/services.ts` の STEP1 の8つのサービスを本物に差し替えた: audio・lipSync（`createAudioSource`・`createLipSyncProducer`、@app/audio）、autoBlink・bodyFollow・expressions（`createAutoBlink`・`createBodyFollowProducer`・`createExpressionController`、@app/core）、calibration（`createCalibrationService`、@app/tracking）、hotkeys（`createHotkeyService`、src/hotkeys）、spout（`createSpoutSink`、src/output/spout）。自動まばたきはスタジオとトラッキングのレイヤー（`createTrackingLayerProducer(..., { autoBlink })`）で同じものを使う。作っただけでは機器を開かず、ホットキーも登録せず、Spout2 でも送らない。
- `apps/desktop/src-tauri/capabilities/default.json` に `global-shortcut:allow-register`・`global-shortcut:allow-unregister-all` を足した（プラグイン 2.4.0 の `global-shortcut:default` は中身が空で、これが無いとホットキーが1つも登録できない）。
- `apps/desktop/src/main.tsx`: 環境設定を読んだあとに `bindSpoutOutput` を呼ぶ（Spout2 を選んでいれば、設定のパネルを開かなくても起動時から送る）。
- 確認のテスト: `apps/desktop/src/services.step1.test.ts`（本物のサービスの組み立て・共有・合成を、機器を開かずに確かめる）、`apps/desktop/e2e/step1.e2e.ts`（本物のアプリの中での STEP1 の通しのテスト）。
- 途中で別のセッションが引き継いだ作業（I-020・I-025 の修正、services.step1.test.ts、カード42の途中まで）は、確かめたうえでそのまま使った。
